# 🚨 IDENTITY COLLISION FIX — Lupopedia 4.0.29

## CRITICAL ISSUE IDENTIFIED

**Symptom**: System crashes when "CAPTAIN WOLFIE STONED LUPOPEDIA LLC 2026" is mentioned

**Root Cause**: **NAME COLLISION** across multiple actor identities causing authentication/resolution conflicts

---

## 🔴 CONFLICTING IDENTITIES

### Problem: 4 Actors with Similar Names

1. **Actor 420** - `stoned_wolfie_ai` (Banned AI)
   - Name: "Stoned Wolfie (AI)"
   - Status: `is_active=0`, `is_deleted=1`, BANNED
   - Email: `stoned.wolfie.ai@banned.local`
   - Type: `agent` (AI test identity)

2. **Actor 10001** - `stonedwolfie` (Banned Human)
   - Name: "Stoned Wolfie"
   - Status: `is_active=0`, `is_deleted=0`, BANNED
   - Email: `stonedwolfie@lupopedia.com`
   - Type: `user` (human test identity)

3. **Actor 1000** - `captain` (Active Human)
   - Name: "CAPTAIN"
   - Status: `is_active=1`, `is_deleted=0`, ACTIVE
   - Email: `captain@lupopedia.com`
   - Type: `human` (legacy operator)

4. **Actor 10000** - `user-10000` (Main Admin)
   - Name: "Captain"
   - Status: `is_active=1`, `is_deleted=0`, ACTIVE
   - Email: (set during installation)
   - Type: `user` (main admin account)

### Collision Point

When user says: **"CAPTAIN WOLFIE STONED LUPOPEDIA LLC 2026"**

System attempts to match:
- ✅ "CAPTAIN" → actor 1000 OR actor 10000? (AMBIGUOUS)
- ✅ "WOLFIE" → Multiple agents named WOLFIE
- ✅ "STONED" → actor 420 OR actor 10001? (AMBIGUOUS)  
- ❌ **CRASH**: Cannot resolve unique identity

---

## 🔧 RESOLUTION STRATEGY

### Option 1: RENAME BANNED TEST IDENTITIES (RECOMMENDED)

**Change actor 420 and 10001 names to NON-COLLIDING values:**

```sql
-- Rename Actor 420 (AI)
UPDATE lupo_actors 
SET name = 'BANNED_TEST_AI_420', 
    slug = 'banned-test-ai-420'
WHERE actor_id = 420;

UPDATE lupo_auth_users 
SET display_name = 'BANNED_TEST_AI_420',
    email = 'banned.test.ai.420@banned.local'
WHERE auth_user_id = 420;

UPDATE lupo_agents
SET agent_name = 'BANNED_TEST_AI_420'
WHERE agent_id = 420;

-- Rename Actor 10001 (Human)
UPDATE lupo_actors 
SET name = 'BANNED_TEST_HUMAN_10001',
    slug = 'banned-test-human-10001'
WHERE actor_id = 10001;

UPDATE lupo_auth_users 
SET display_name = 'BANNED_TEST_HUMAN_10001',
    username = 'banned_test_human_10001',
    email = 'banned.test.human.10001@banned.local'
WHERE auth_user_id = 10001;
```

**Result**: 
- ✅ "CAPTAIN WOLFIE STONED" no longer matches banned test identities
- ✅ Actor 1000 and 10000 remain with "CAPTAIN" names (legitimate)
- ✅ Test identities clearly marked as non-operational

### Option 2: ADD IDENTITY RESOLUTION PRIORITY

**Modify ANUBIS_Resolver.php to prioritize ACTIVE actors:**

```php
// In ANUBIS_Resolver.php, add priority resolution
public function resolveActorByName($name) {
    $a_table = $this->db->quoteIdentifier($this->prefix . 'actors');
    
    // Priority 1: Active, non-deleted, non-banned
    $row = $this->db->fetchRow(
        "SELECT actor_id FROM " . $a_table . " 
         WHERE name LIKE :name 
         AND is_active = 1 
         AND is_deleted = 0
         AND actor_id NOT IN (SELECT actor_id FROM " . $this->prefix . "banned_actors WHERE is_deleted = 0)
         ORDER BY actor_id ASC
         LIMIT 1",
        array('name' => '%' . $name . '%')
    );
    
    if ($row) {
        return (int) $row['actor_id'];
    }
    
    // Priority 2: Any non-banned actor
    $row = $this->db->fetchRow(
        "SELECT actor_id FROM " . $a_table . " 
         WHERE name LIKE :name 
         AND actor_id NOT IN (SELECT actor_id FROM " . $this->prefix . "banned_actors WHERE is_deleted = 0)
         ORDER BY is_active DESC, is_deleted ASC, actor_id ASC
         LIMIT 1",
        array('name' => '%' . $name . '%')
    );
    
    return $row ? (int) $row['actor_id'] : null;
}
```
