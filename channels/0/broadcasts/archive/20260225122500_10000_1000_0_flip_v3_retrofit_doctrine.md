# DOCTRINE #14: FLIP v3 RETROFIT FOR ARTIFACTS + CHANNELS + ACTORS

**Status:** MANDATORY  
**Effective:** Version 4.0.43+  
**Authority:** Captain Wolfie (10000)  
**Implementation:** Two-phase retrofit strategy

## Overview

Every .md file under `artifacts/`, `channels/`, and `actors/` MUST have a FLIP v3 header that allows IDE/importer to answer critical questions WITHOUT reading the database: where it lives, when it was created, who made it, what it is, and how it relates.

## What The Header Must Guarantee

For every .md file, the FLIP header must enable answering these questions without database access:

### 1. Where does this file live canonically?
- `artifact_path` — Absolute path from repo root
- `federated_node_id` — From folder name: `artifacts/<id>/...`
- `artifact_id` — Stable ID (if unknown, generate deterministically)

### 2. When was it created (UTC BIGINT)?
- `created_ymdhis` — UTC YYYYMMDDHHMMSS
- `created_source` — How timestamp was determined
- `created_confidence` — 0.0-1.0 reliability score

### 3. Who made it?
- `actor_id` — If unknown: 0 or 10000 based on rules
- `actor_source` — How actor was determined
- `actor_confidence` — 0.0-1.0 reliability score

### 4. What is it and how does it relate?
- `artifact_type` — document|message|directive|code|log|index|unknown
- `artifact_kind` — Controlled vocabulary
- `relations[]` — Parent/child/derived-from/mentions/etc.

Everything else is enrichment.

## Two-Phase Retrofit Strategy

### Phase A: "Minimum FLIP" for 100% Coverage

**Goal:** Every file becomes importable and locatable.

**Input Sources (Always Available):**
- Filesystem path
- Filename
- Folder ancestry
- File modified time (mtime)
- Optional: git history if repo has it

**Outputs:**
- FLIP v3 header + footer added to every .md
- Manifest CSV/JSON of everything changed
- Quarantine folder for unparseable weirdness (ANUBIS)

**Minimum Required Fields:**
```yaml
flip_version: 3
system_version: "4.0.43"
artifact_id: "sha1:..."
federated_node_id: 42
artifact_path: "artifacts/42/foo/bar.md"
artifact_type: "document"
artifact_kind: "artifact_md"
actor_id: 0
actor_source: "unknown"
actor_confidence: 0.0
created_ymdhis: 20260224091530
created_source: "mtime"
created_confidence: 0.5
updated_ymdhis: 20260224091530
is_deleted: 0
deleted_ymdhis: 0
```

### Phase B: "Detailed FLIP" Enrichment Pass

**Goal:** Add "why", semantic tags, and relation graph.

**Input Signals:**
- Content heuristics (first heading, "From:" lines, "Actor:" strings)
- Nearby registry.json (channels/actors/artifacts)
- Artifacts metadata files if any
- Optional: commit author mapping → actor aliases map

**Additional Fields:**
```yaml
title: "..."
summary: "..."
why: "why this exists / intent"
semantic_tags: ["lupopedia","migration","legacy","needs_review"]

  - rel: "derived_from"
    target: "artifacts/42/legacy/import.txt"
    note: "source file"
  - rel: "mentions_actor"
    target_actor_id: 1003
  - rel: "mentions_channel"
    target_channel_id: 0
delegation_chain: "10000:1003"
```

## Deterministic artifact_id Generation

**If legacy file doesn't have an ID in content:**
```
artifact_id = sha1("artifacts/<node>/<relative_path>" + "\n" + file_bytes_sha1)
```

**For actors/ files:**
```
artifact_id = sha1("actors/<actor_id>/<relative_path>" + "\n" + file_bytes_sha1)
```

**For channels/ files:**
```
artifact_id = sha1("channels/<channel_id>/<relative_path>" + "\n" + file_bytes_sha1)
```

**Store Both:**
- `path_sha1` — Stable across machines
- `content_sha1` — Detects content changes

**Benefits:**
- Stable across machines
- Avoids collisions
- Makes "skip duplicates safely" trivial in importer

## Special Handling for actors/ Files

**Actor files have special requirements:**

1. **Extract actor_id from path:**
   - Path format: `actors/<actor_id>/<filename>.md`
   - `actor_id` is the folder name (numeric)
   - Set `actor_confidence = 1.0` (explicit from path)

2. **Set artifact_type appropriately:**
   - `artifact_type: "actor_metadata"` for actor profile/metadata files
   - `artifact_type: "actor_document"` for actor-related documentation

3. **Add actor-specific relations:**
   ```yaml
   relations:
     - rel: "describes_actor"
       target_actor_id: <actor_id>
     - rel: "part_of_actor_folder"
       target: "actors/<actor_id>/"
   ```

4. **Use actor registry for enrichment:**
   - Cross-reference with `actors/registry.json`
   - Add actor display_name, canonical_slug to metadata
   - Validate actor_id exists in registry

**Example actors/ FLIP header:**
```yaml
---
flip_version: 3
system_version: "4.0.43"
artifact_id: "sha1:..."
federated_node_id: 10000  # from actors/<id>/
artifact_path: "actors/10000/profile.md"
artifact_type: "actor_metadata"
artifact_kind: "actor_profile"
actor_id: 10000
actor_source: "explicit"
actor_confidence: 1.0
created_ymdhis: 20260224091530
created_source: "mtime"
created_confidence: 0.5
semantic_tags: ["actor", "profile", "human"]
relations:
  - rel: "describes_actor"
    target_actor_id: 10000
  - rel: "part_of_actor_folder"
    target: "actors/10000/"

---
```

## Inferring created_ymdhis (UTC) Without Lying

**Priority Order:**
1. If file content contains a timestamp you trust → `explicit` (confidence high)
2. Else if git history exists → `git` (confidence medium-high)
3. Else filesystem mtime → `mtime` (confidence medium-low)
4. Else set to retrofit time → `unknown` (confidence 0)

**Always:**
- Convert to UTC
- Store as BIGINT YYYYMMDDHHMMSS
- Record `created_source` and `created_confidence`

**Never lie about confidence.** If you don't know, say so.

## Inferring actor_id (Keep It Honest)

**Priority Order:**
1. If file already names an `actor_id` explicitly → use it
2. Else parse "From:" / "Actor:" / signature patterns → map via `actors/aliases.csv`
3. Else infer from containing folder rules (e.g., known agent folder) → medium confidence
4. Else default to `actor_id = 0` (unknown) OR `10000` if you choose "owner default" policy

**Always Store:**
- `actor_source` — How actor was determined
- `actor_confidence` — 0.0-1.0 reliability

**Never guess silently.**

## Relation Graph: What "Detailed FLIP" Means

**For artifacts, relations should cover at least:**
- `parent_of` / `child_of` — Folder structure / chunking
- `derived_from` — Imports/conversions
- `references` — Links to other artifacts by path
- `mentions_actor` — `target_actor_id`
- `mentions_channel` — `target_channel_id`
- `produced_by_command` — `system_commands/system_command_id`
- `part_of_thread` — If you can map to channels threads later

**Even if you can't resolve a target yet, allow a placeholder:**
```yaml
target: "unresolved:path:..."
```

## The "Do This At Scale" Pipeline

### 1. Scan
Walk `artifacts/**/*.md`, `channels/**/*.md`, and `actors/**/*.md`

### 2. Detect
Does it already have FLIP frontmatter?
- If yes: validate and enrich
- If no: create from scratch

### 3. Extract
- `federated_node_id` from `artifacts/<id>/`, `channels/<id>/`, or `actors/<id>/`
- `path`, `filename`
- `content_hash`
- Timestamps (see rules)
- Actor hints (via `actors/aliases.csv`)
- Relation hints (links, "see also", "artifact:" tokens)
- For actors/ files: extract `actor_id` from folder name or filename

### 4. Write
- Prepend YAML frontmatter
- Append footer block
- Preserve original content

### 5. Log
Write `docs/status/flip_retrofit_manifest_4_0_43.jsonl`:
- Include before/after hashes
- Record all changes
- Track confidence scores

### 6. Quarantine
If file is malformed (binary, huge, encoding issues):
- Route to ANUBIS folder
- Add manifest entry
- Log for manual review

### 7. Validate
Run validator that ensures required keys exist for 100% of files:
- `artifact_path`
- `federated_node_id`
- `artifact_id`
- `created_ymdhis`
- `actor_id`

## Confidence Score Guidelines

**1.0 — Explicit:** Data directly stated in file content  
**0.9 — Registry:** Data from canonical registry  
**0.7 — Git:** Data from git history  
**0.5 — Mtime:** Data from filesystem metadata  
**0.3 — Inferred:** Data from content heuristics  
**0.1 — Guessed:** Data from weak signals  
**0.0 — Unknown:** No data available, using default  

## Actor Source Guidelines

**explicit:** `actor_id` stated in file content  
**registry:** Mapped via `actors/registry.json`  
**alias:** Mapped via `actors/aliases.csv`  
**git:** Extracted from git commit author  
**folder:** Inferred from containing folder  
**inferred:** Parsed from "From:" / "Actor:" patterns  
**unknown:** No actor information available  

## Created Source Guidelines

**explicit:** Timestamp stated in file content  
**git:** Extracted from git commit timestamp  
**mtime:** Filesystem modification time  
**unknown:** No timestamp available, using retrofit time
