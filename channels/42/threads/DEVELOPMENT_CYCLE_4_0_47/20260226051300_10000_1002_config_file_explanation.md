# Lupopedia Configuration Files: lupo-config.php vs lupopedia-config.php

## Overview
Lupopedia uses **two separate configuration files** with distinct purposes and creation contexts:

### lupo-config.php (Generated During Installation)
**Purpose**: System-generated configuration file created by the installation wizard
**When Created**: During `install.php` execution
**Contents**:
- Database connection settings
- Default security and application configurations
- Installation-specific settings (paths, versions, etc.)
- **Read-Only**: Should not be manually edited

### lupopedia-config.php (User Configuration)
**Purpose**: User-editable configuration file for custom settings
**When Created**: Manually by site administrators
**Contents**:
- Custom database credentials
- Override settings for security, applications, channels
- User preferences and customizations
- **Editable**: Can be safely modified by administrators

## Key Differences

### File Generation Context
| Aspect | lupo-config.php | lupopedia-config.php |
|---------|------------------|-------------------|
| **Creation** | Installation wizard | Manual admin setup |
| **Permissions** | Read-only (system) | Read-write (user) |
| **Backup** | Auto-generated | Manual maintenance |
| **Override Behavior** | Not overridden | Overrides system defaults |

### Search Priority in index.php
The `index.php` searches for configuration files in this specific order:

1. **`lupo-config.php`** (DOCUMENT_ROOT level)
   - **Location**: `dirname($_SERVER['DOCUMENT_ROOT']) . '/lupopedia-config.php'`
   - **Use Case**: Standard installations, most secure
   - **Priority**: Highest - this is the preferred configuration file

2. **`lupo-config.php`** (Public path + subdirectory)
   - **Location**: `dirname($_SERVER['DOCUMENT_ROOT']) . LUPOPEDIA_PUBLIC_PATH . '/lupopedia-config.php'`
   - **Use Case**: Subdirectory installations (e.g., Lupopedia in `/lupopedia/` subdirectory)
   - **Priority**: Medium - fallback for when main config doesn't exist

3. **`lupopedia-config.php`** (Internal path)
   - **Location**: `LUPOPEDIA_PATH . '/lupopedia-config.php'`
   - **Use Case**: Internal system access, development
   - **Priority**: Lowest - only used when other files are unavailable

### Why Both Files Exist

In a **standard installation** (Lupopedia in web root):
- Only `lupo-config.php` exists at DOCUMENT_ROOT level
- `lupopedia-config.php` is created during installation and never used again

In a **subdirectory installation** (Lupopedia in `/lupopedia/` subdirectory):
- `lupo-config.php` exists at DOCUMENT_ROOT level (contains basic settings)
- `lupopedia-config.php` exists in subdirectory (contains user customizations)
- Both files serve different purposes and can coexist

### Configuration Loading Behavior

**Constants Definition Order**:
1. `LUPOPEDIA_PATH` - Base filesystem path
2. `LUPOPEDIA_ABSPATH` - Absolute path to includes
3. `LUPOPEDIA_PUBLIC_PATH` - Web-accessible public path
4. `LUPOPEDIA_CONFIG_LOADED` - Prevents duplicate loading

**File Loading Sequence**:
1. `lupo-config.php` defines essential constants first
2. `bootstrap.php` loads the configuration file
3. Other modules can safely access all defined constants

## Security Implications

### lupo-config.php (System File)
- **Protected**: Should not be web-accessible in production
- **Contains**: Database credentials, system paths, security settings
- **Recommendation**: Place outside web root or restrict web access

### lupopedia-config.php (User File)
- **Accessible**: Can be web-accessible for admin interface
- **Contains**: User customizations, feature flags, integration settings
- **Flexibility**: Allows site-specific overrides without affecting system stability

## Best Practices

### For Administrators
1. **Edit `lupopedia-config.php`** for system-wide changes
2. **Edit `lupopedia-config.php`** for user preferences and customizations
3. **Never edit `lupo-config.php`** directly - it's regenerated by installer
4. **Backup both files** before making changes
5. **Use proper constants** - `LUPOPEDIA_CONFIG_PATH` for user config, `LUPOPEDIA_PATH` for system config

### For Developers
1. **Check `LUPOPEDIA_CONFIG_LOADED`** before accessing configuration
2. **Use `get_cfg()` helper** instead of direct file access
3. **Understand the hierarchy** - system config vs user config
4. **Respect the search order** in index.php

## Resolution

The **dual configuration system** is intentional and provides:

1. **System Stability**: Core settings in `lupo-config.php` remain consistent
2. **User Flexibility**: Custom settings in `lupopedia-config.php` allow site adaptation
3. **Clear Separation**: System vs user configuration prevents conflicts
4. **Installation Support**: Works correctly in both standard and subdirectory setups
5. **Development Clarity**: Different files serve different, well-documented purposes

This design ensures that Lupopedia can handle diverse installation scenarios while maintaining configuration integrity and providing administrators with appropriate flexibility for site customization.
