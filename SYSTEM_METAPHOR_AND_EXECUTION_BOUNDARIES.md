# Lupopedia — Symbolic Naming and Execution Boundaries

## Purpose

Lupopedia uses symbolic, literary, philosophical, mythological, scientific, and cultural naming conventions throughout the system.

These names help humans reason about:

* architecture
* relationships
* memory
* responsibility
* transitions
* identity
* failure states
* semantic meaning

However:

Symbolic naming does NOT automatically define runtime behavior.

Actual execution behavior is determined by:

* PRDs
* validators
* deterministic code
* database doctrine
* filesystem doctrine
* explicit routing rules
* schemas
* tests
* documented system constraints

This file exists to prevent confusion between:

* metaphorical meaning
* symbolic inspiration
* conceptual language
* actual executable behavior

---

# Core Boundary Rule

Names carry meaning.

Rules carry behavior.

Code carries execution.

Metaphor may describe a system.

Metaphor does NOT replace deterministic implementation.

# Agent Soul Layer Files

Agent folders may contain semantic “soul-layer” files.

These files describe:

* behavioral ideals
* responsibilities
* failure patterns
* learned wisdom
* stable identity tendencies

These files are descriptive doctrine layers.

They do NOT bypass validators, PRDs, or execution rules.

Canonical soul-layer files:

```text id="6t8mws"
/agents/<agent_id>/

soul_PONO.md
soul_KAPU.md
soul_KULEANA.md
soul_PILAU.md
soul_AGAPE.md
soul_INVARIANT.md
```

---

## soul_PONO.md

Defines:

* ideal aligned behavior
* desired operational state
* corrective direction
* healthy execution patterns

PONO describes what the agent SHOULD move toward.

---

## soul_KAPU.md

Defines:

* forbidden behaviors
* hard boundaries
* protected constraints
* non-negotiable limits

KAPU defines what the agent MUST NOT violate.

---

## soul_KULEANA.md

Defines:

* responsibilities
* operational ownership
* required duties

---

## soul_PILAU.md

Defines:

* corruption patterns
* recurring mistakes
* anti-patterns
* known destabilizing behaviors
* failure modes
* prior operational errors

PILAU represents what has gone wrong.

This file should remain operational and analytical.

It MUST NOT become an emotional blame log.

## soul_AGAPE.md

Defines:

* wisdom extracted from mistakes
* corrective insight
* stabilized learning
* recovered understanding
* successful recovery patterns

AGAPE represents what was learned from PILAU.

Relationship:

```text id="jlwmby"
PILAU → failure observed
AGAPE → wisdom extracted
```
