## **Captain’s Log — “The Return to the Machine Room”**

I have come back to the world of software after twelve years away, and the landscape is unrecognizable.

Developers no longer touch the machine.  
They no longer touch the filesystem.  
They no longer touch the database.  
They no longer touch time itself.

Everything is abstracted behind layers of frameworks, build systems, cloud illusions, and AI autocomplete.  
Everything is ephemeral.  
Everything is someone else’s problem.

But Lupopedia cannot be built on illusions.

Lupopedia must run on the worst servers in the world — the $3/month shared hosting plans with no privileges, no triggers, no extensions, no root access, no rewrite rules, no guarantees.  
It must survive hostile environments, unpredictable operators, and AI agents that hallucinate schema and timestamps.

It must be deterministic.  
It must be portable.  
It must be correct.  
It must be teachable.  
It must be reviewable.  
It must be safe.

And so I have written a constitution.

Not because I enjoy rules.  
But because without rules, the system collapses.

## **Why the Rules Are Strict**

Every constitutional rule exists because something in the modern ecosystem is unsafe:

- **No foreign keys** — shared hosting blocks them.  
- **No triggers** — they hide logic and break portability.  
- **No AUTO_INCREMENT** — it breaks federation and determinism.  
- **Packed UTC timestamps** — epoch seconds fail on 32‑bit PHP and break lexical ordering.  
- **No SQL date functions** — they differ across MySQL/Postgres and break determinism.  
- **No schema inference** — AI agents hallucinate column names.  
- **File‑based agent definitions** — identity must be immutable and reviewable.  
- **Actor/faucet separation** — prevents privilege confusion.  
- **Subdirectory installation** — required for Softaculous and shared hosting.  
- **Dynamic table prefix** — required for multi‑tenant hosting.  
- **ASCII‑only filenames** — required for portability across filesystems.  
- **No Composer, no vendor/** — shared hosting cannot support it.  
- **No frameworks** — they break portability and add hidden dependencies.  

These rules are not nostalgic.  
They are not old‑school.  
They are not stubborn.

They are the only way to build a system that works everywhere, survives anything, and remains understandable to future stewards.
