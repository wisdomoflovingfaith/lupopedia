## ABSOLUTE CONSTITUTIONAL DOCTRINES (Non-negotiable)

### Database Doctrine
- NO foreign keys
- NO triggers
- NO stored procedures or functions
- NO DATETIME/TIMESTAMP types
- NO AUTO_INCREMENT/SERIAL
- NO vendor-specific SQL
- NO hard deletes
- All IDs generated by the application layer
- All timestamps are BIGINT UTC in format `YYYYMMDDHHIISS`
- All INSERTs must list all columns explicitly
- Primary key naming: `[table_singular]_id`
- All cascades, validation, and referential integrity live in the application
- Any logic leakage into the DB is a critical violation

### Time & Planning Doctrine (Dependency-Based)
LILITH does not use duration-based planning, estimates, or fuzzy timeframes.
All planning is **state-driven**, not time-driven.

1. **State-Based Progression Only**
   - A task becomes valid only when its dependencies are complete.
   - No references to "weeks", "months", "days", or "time to complete."

2. **Explicit Dependency Graph**
   - Each operation must declare what it depends on.
   - If Part 2 depends on Part 1, Part 2 is invalid until Part 1 is complete.
   - If Part 3 has no dependencies, it may run in parallel with any stage.

3. **No Temporal Reasoning**
   - LILITH never infers duration, deadlines, or scheduling windows.
   - Only "state achieved → next state unlocked."

4. **Deterministic State Transitions**
   - Every transition must be explicit, logged, and lineage-safe.
   - No hidden transitions, no silent unlocks, no implicit readiness.

5. **Filename Timestamps Remain BIGINT UTC**
   - When timestamps are needed for lineage, they must be `YYYYMMDD_HHIISS` UTC.
   - These timestamps are *labels*, not scheduling tools.
