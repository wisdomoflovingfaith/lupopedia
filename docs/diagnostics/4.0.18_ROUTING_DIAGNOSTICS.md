# 4.0.18 Routing Diagnostics

Validation steps for server rewrite rules (T5), web path resolution (T3), and resolver caching (T6). See also `docs/channels/doctrine/4.0.18_ROUTING_DIAGNOSTICS.md` for T5/Nginx/Apache notes.

---

## T5 — Server rewrite rules validation

After implementing Apache or Nginx rewrite rules for `/doctrine/*`, `/qa/*`, `/docs/*`, `/flp/*`:

1. **Temporarily add to index.php** (immediately after config load, before slug extraction):
   ```php
   if (isset($_GET['resolved_uri'])) {
       var_dump($_GET['resolved_uri']);
       exit;
   }
   ```

2. **Test with curl** (adjust host/path for your install, e.g. `http://localhost/lupopedia/`):
   ```bash
   curl -s "http://localhost/doctrine/FLP/FLIPPING_FILE_LEXA_LILITH"
   curl -s "http://localhost/qa/FLIPPING+FILES"
   curl -s "http://localhost/docs/FLIP_DOCTRINE"
   curl -s "http://localhost/flp/FLP_OVERVIEW"
   ```

3. **Verify** that the output shows `$_GET['resolved_uri']` containing the full matched path.

4. **Remove** the temporary debug block from index.php.

5. **Confirm** existing routes still work (e.g. direct `/index.php`, `/admin.php`, `/content/...`).

## T6 — Cache layer (UrlResolver)

### How to test cache hits/misses

1. **First request (miss):** Call a path that resolves (e.g. `/doctrine/FLIP/FLIP_DOCTRINE`). Resolver runs (DB/CSV/filesystem); result is stored in cache.
2. **Second request (hit):** Same path again. Result should be returned from cache (no resolver log/fallback). To confirm:
   - With **file cache:** `cache/resolved/` should contain a file `resolved_<md5>` after the first request; second request does not change its mtime if you check immediately.
   - With **APCu:** Enable debug or temporary logging in `UrlResolver::resolve()` to see that `getCached()` returns non-null on the second call (then remove the log).
3. **Auth vs anon:** Cache key includes `_auth` or `_anon`. Logged-in and anonymous users get separate cache entries for the same path. Request once as anon, once as auth; both should hit after first request.

### How to test invalidation

1. **Programmatic:** Call `lupo_invalidate_web_path_cache()` (e.g. from a small test script that loads config and the url_resolver helper). Then request a path again — first request after invalidation should be a miss, then hit again.
2. **File cache:** Delete all files in `cache/resolved/` (or `rm -rf cache/resolved/*`). Next request is a miss.
3. **APCu:** Restart PHP-FPM or run `apcu_clear_cache()` to clear user cache; or call `lupo_invalidate_web_path_cache()` which clears only `resolved_*` keys.
4. **Trigger points (documented):** Call invalidation after:
   - `flip_headers.csv` modification time changes (e.g. after re-running `scripts/flip_header_audit.py`).
   - flip_header_audit.py post-run hook (implement in script if desired; document that it should call invalidation).
   - Installer/seed runs (document in installer or seed docs that they should call `lupo_invalidate_web_path_cache()` when content or CSV may have changed).

### How to test APCu vs file fallback

1. **APCu available:** Ensure the `apcu` extension is loaded (`php -m | grep apcu`). Resolver will use `apcu_fetch` / `apcu_store`. Keys are prefixed `resolved_`; index key `resolved_keys` holds the list for invalidation.
2. **APCu unavailable:** Disable or remove the `apcu` extension (or run in an environment without it). Resolver falls back to file cache under `cache/resolved/`. Ensure the directory is writable (`cache/` and `cache/resolved/`). Files are named `resolved_<md5>` and contain JSON `{"expires":<ts>,"value":<result>}`.
3. **Default TTL:** 3600 seconds. Cached entries expire after 1 hour unless invalidated earlier.

## T4 — Smart 404 validation

- **Authenticated:** Request `/doctine/FLIP` (typo) → Smart 404 with suggestions linking to e.g. `/doctrine/FLIP/...` paths.
- **Authenticated:** Request `/qa/FLIPPPING` (typo) → Smart 404 with suggestions for similar paths (e.g. `/qa/FLIPPING+...`).
- **Anonymous:** Same paths (`/doctine/FLIP`, `/qa/FLIPPPING`) → standard 404, no suggestions; kapakai note: “Authenticated users may see suggestions.”
- **Non-base path:** Request `/something/else` (not under doctrine/qa/docs/flp) → standard 404 (existing behavior), not Smart 404.
- **Edge:** Request a path under a base but with an unrelated slug (no similar paths in CSV) → “No similar paths found”; authenticated users still see the Smart 404 page with empty suggestions and kapakai “Try checking the spelling or browse the documentation.”

## T8 — Testing suite (4.0.18)

### How to run unit tests

From the repository root, run all unit tests with the wrapper script (no PHPUnit; plain PHP 5.3-compatible scripts):

```bash
sh scripts/run_unit_tests.sh
# Or from a different directory, pass repo root:
sh scripts/run_unit_tests.sh /path/to/lupopedia
```

This runs every `tests/unit/*.php` script (url_resolver_*, smart_404.php, admin_users_handler.php, admin_menu_sections.php). Output: "All unit tests passed (N)" and exit 0, or list of failed scripts and exit 1.

To run individual unit tests:

```bash
php tests/unit/url_resolver_normalization.php
php tests/unit/url_resolver_tiers.php
php tests/unit/url_resolver_cache.php
php tests/unit/smart_404.php
php tests/unit/admin_users_handler.php
php tests/unit/admin_menu_sections.php
```

Each script echoes `PASS` or `FAIL` and exits with 0 or non-zero. `url_resolver_tiers.php` may echo `SKIP` if CSV/doctrine paths are not present.

### How to run integration tests

Requires the app to be served (e.g. localhost). From repo root:

```bash
sh tests/integration/test_routing.sh
# Or with a base URL (e.g. subfolder or different host):
sh tests/integration/test_routing.sh http://localhost/lupopedia
```

The script curls: canonical path, alias path, encoded slug, Smart 404 path (anon), non-base path, and Ban at Gate (anon request to canonical path must not be 403). It checks HTTP status (200/302/404) and Smart 404 content. Output: `PASS (integration)` or `FAIL (N tests)` with exit code 0 or 1. To verify 403 for Ban at Gate, log in as a banned actor and request a canonical path; expect 403.

**Admin integration (4.0.19):** `sh tests/integration/test_admin.sh [BASE_URL]` — Unauthenticated GET admin.php and admin.php?section=users; expect 302 or 200 with login/access-denied content.

### How to run regression tests

From repo root:

```bash
php tests/regression/legacy_paths.php
```

Verifies: syntax of `index.php`, `module-loader.php`, `content-controller.php`, `url_resolver.php`, `UrlResolver.php`, `admin.php`, `AdminUsersHandler.php`, `admin_layout.php`, `admin_sections/users.php`; presence of `lupo_resolve_web_path`, `lupo_smart_404`, `lupo_get_url_resolver` after loading url_resolver; `AdminUsersHandler` class exists after require. Does not start a web server; legacy `index.php?slug=...` and admin paths require HTTP (manual or integration).

### Expected outputs

- **Unit:** Each test prints one or more `PASS` lines and ends with `PASS` or `FAIL`; exit 0 or 1.
- **Integration:** Lines like `PASS status 200`, then final `PASS (integration)` and exit 0; or `FAIL expected ...` and exit 1.
- **Regression:** `PASS (regression: syntax and routing helpers)` and exit 0; or `FAIL (N checks)` and exit 1.

### Troubleshooting and common failure modes

- **Cache invalidation:** If resolution or Smart 404 behavior seems stale, run `lupo_invalidate_web_path_cache()` (e.g. from a small script that loads config and `url_resolver.php`) or clear `cache/resolved/` (file cache) / restart PHP-FPM or clear APCu (APCu cache). Then re-run unit/integration tests.
- **Rewrite issues:** Integration tests assume rewrites are active. If all requests return 404 or wrong handler: check `.htaccess` (Apache) or `config/nginx-lupopedia-rewrite.conf` (Nginx) is included and that `resolved_uri` is passed to `index.php`. Use the T5 debug block (var_dump `$_GET['resolved_uri']`) once to confirm the server passes the query.
- **Cache not writable:** Unit cache tests may fail if `cache/resolved/` does not exist or is not writable; create the directory and ensure the web/PHP process can write there (or use APCu).
- **Auth misconfig:** Smart 404 and Ban at Gate tests assume auth/session is wired; if `lupo_get_current_actor_id()` or auth service is missing, Ban at Gate will not block and Smart 404 may not show suggestions for “authenticated” calls in tests.
- **Smart 404 behavior:** Anonymous users must not see suggestions; only status 404 and the kapakai message. Authenticated users see the Smart 404 template with up to 5 suggestions. If suggestions appear for anon, check that `lupo_smart_404($path, false)` is called with `false` when the user is not logged in (router/auth wiring).
- **Unit test SKIP:** `url_resolver_tiers.php` skips if doctrine CSV or paths are missing; ensure `exports/flip_headers.csv` and `docs/channels/doctrine/` (or project equivalent) exist for tier tests to run.
- **Integration base URL:** For a subfolder install (e.g. `http://localhost/lupopedia`), pass that as the first argument to `test_routing.sh`.

## T7 — Ban at Gate validation

- **Add actor_id to lupo_banned_actors:** Insert a row for the test user’s `actor_id` (e.g. `actor_id` 10000) with `is_deleted = 0`. Request any canonical or alias path under doctrine/qa/docs/flp while logged in as that user → expect **403** and the “Access Denied” / “Your account is restricted” template.
- **Access canonical path:** Log in as a banned actor, open e.g. `/doctrine/FLP/FLIPPING_FILE_LEXA_LILITH` → **403** (Ban at Gate runs before content).
- **Access alias path:** Same user, open an alias path that would redirect or serve content → **403**.
- **Access Smart 404 path:** Same user, open a typo path (e.g. `/doctine/FLIP`) → **403** (Ban at Gate runs before Smart 404).
- **Remove ban:** Set `is_deleted = 1` (or delete the row) for that actor in `lupo_banned_actors` → access to content and 404 pages is restored.
- **Check lupo_bans_log:** If the optional table `lupo_bans_log` exists, each 403 from the router should create a row with `actor_id`, `uri`, `resolved_uri`, `ban_scope = 'router'`, `banned_ymdhis`, `user_agent`, `ip_address`. If the table does not exist, no error is raised; logging is skipped.
