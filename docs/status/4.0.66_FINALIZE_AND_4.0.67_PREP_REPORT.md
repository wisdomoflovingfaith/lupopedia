## 4 Install / Upgrade Review

### Execution path (upgrade)

1. **Credentials step** → DB connection; detect `livehelp_*` tables or Crafty config → set `$_SESSION['lupo_install_type'] = 'upgrade'`.
2. **Bootstrap (upgrade):** Run in order: `install_new_lupopedia.sql`, `seed_registry_comprehensive_4.0.45.sql`, `seed_registry_additional_csv_entities_4.0.45.sql`, `seed_registry_open_4.0.45.sql`, `seed_actors_agents_4.0.45.sql`, `InstallWizardChannels::createReservedSystemChannels`; store log in `$_SESSION['lupo_bootstrap_log']`.
3. **Normalize** → identity normalization (if applicable).
4. **Run step:** `import_from_old_crafty_syntax.sql`, `InstallWizardDepartments::ensureSystemDepartment`, `InstallWizardChannels::createOperatorChannels` / `ensureOperatorChannels`, optionally `drop_old_crafty_syntax_tables.sql`; then MD import, anubis migrations, default sessions, FLARE seeds, activations, etc.

### Files inspected

- `install.php` — version fallback and wizard flow; upgrade detection and SQL run order confirmed.
- `lupo-database/lupopedia/mysql/import/import_from_old_crafty_syntax.sql` — uses `lupo_dialog_threads`, `lupo_dialog_messages` (TRUNCATE + INSERT); comment references `lupo_actor_channel_roles`. No references to `lupo_threads`, `lupo_messages`, or `lupo_rolls`.
- `lupo-database/lupopedia/mysql/install/install_new_lupopedia.sql` — contains `lupo_dialog_messages` (with `metadata_json`), `lupo_tasks` (with `metadata_json`), and other canonical tables.

## 10 Remaining Risks

- **Atom loader path:** Version at runtime comes from `GLOBAL_CURRENT_LUPOPEDIA_VERSION` in `config/global_atoms.yaml`. The repo uses `lupo-config/config/global_atoms.yaml`; if the app resolves `config/` elsewhere (e.g. different symlink or path), the 4.0.67 value must be present there too.
- **Post-install web load:** Not exercised in this session. If the manual test shows missing registry rows, wrong config path, or code expecting a table that does not exist after upgrade, those should be fixed and noted in a 4.0.67 patch or 4.0.68.
- **Reserved ID / AUTO_INCREMENT:** The wizard sets `lupo_actors` AUTO_INCREMENT to at least 10000 for upgrade. Doctrine prefers explicit IDs; this is existing wizard behavior and was not changed.
