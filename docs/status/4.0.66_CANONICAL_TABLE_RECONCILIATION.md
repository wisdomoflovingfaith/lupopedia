# 4.0.66 Canonical Table Reconciliation

**Date:** 2026-03-08  
**Purpose:** Align 4.0.66 multi-agent services with existing canonical schema (TOON-backed). No duplicate tables.

**Update (4.0.69):** The tables `lupo_threads` and `lupo_messages` have been **removed** from the schema. Use **`lupo_dialog_threads`** and **`lupo_dialog_messages`** only. See [COMMUNICATION_DOCTRINE.md](../../lupo-docs/doctrine/COMMUNICATION_DOCTRINE.md) and CHANGELOG 4.0.69.

## Intended 4.0.66 concept → Canonical table

| Intended concept | Existing canonical table | Action |
|------------------|--------------------------|--------|
| threads | `lupo_dialog_threads` | Reuse; ChannelService does not insert threads (filesystem-only for thread list). Message persistence uses `lupo_dialog_messages`. |
| messages | `lupo_dialog_messages` | Reuse; ChannelService `postMessage()` updated to INSERT into `lupo_dialog_messages` with correct columns. |
| channel roles | `lupo_actor_channel_roles` | Reuse; no service was referencing `lupo_rolls`. |
| agent tasks | `lupo_tasks` | Reuse; TaskService already used `lupo_tasks`. `parent_agent_id` stored in `metadata_json`. |
| consensus metadata | `lupo_tasks.metadata_json` | Reuse; no new columns. |

## Answers to required questions

1. **Does `lupo_dialog_threads` fulfill the role of `lupo_threads`?** Yes. Same concept (per-channel dialogue threads). PK `dialog_thread_id`, has `channel_id`, `created_by_actor_id`, `status`, etc.
2. **Does `lupo_dialog_messages` fulfill the role of `lupo_messages`?** Yes. Same concept (messages in threads/channels). PK `dialog_message_id`, has `dialog_thread_id`, `channel_id`, `from_actor_id`, `message_text`, etc.
3. **Does `lupo_actor_channel_roles` fulfill the role of `lupo_rolls`?** Yes. Same concept (actor roles per channel). PK `actor_channel_role_id`, has `actor_id`, `channel_id`, `role_key`, etc.
4. **Gaps after reusing canonical tables:** None for 4.0.66 service behavior. Optional future: add `parent_agent_id` column to `lupo_tasks` if desired; currently stored in `metadata_json`.
5. **Service methods pointing at non-canonical names:** ChannelService `postMessage()` was inserting into `lupo_messages` (non-existent). TaskService `createTask()` referenced `parent_agent_id` column (not in canonical `lupo_tasks`); now uses `metadata_json`.
6. **Schema changes necessary:** None. No new tables; no new columns in install SQL. All changes are PHP and docs/seeds.
