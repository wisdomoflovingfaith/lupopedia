---

## PHILOSOPHY

### Simplicity Over Complexity

- prefer minimal solutions  
- avoid unnecessary abstraction  
- remove non-essential layers  

---

### Dependencies Are Debt

- external dependencies introduce failure points  
- systems should minimize reliance on external tooling  

---

### Survival Without the Creator

- systems must operate without continuous human intervention  
- automation must not depend on a single operator  

---

### Fallback Systems Are Mandatory

Systems must never hard-fail.

Example model:

- best case → use full capability  
- degraded case → fallback  
- failure case → still produce usable output  

---

### Graceful Degradation

If a component fails:

- provide alternative behavior  
- provide guidance  
- never terminate completely

## DESIGN MODEL

### Build From Worst Case First

Start with:

- minimal environment  
- restricted capabilities  
- limited access  

Then scale upward.

Result:

- system works in all environments  

---

### Orphan Handling

Systems must tolerate missing relationships.

- missing parent → assign default  
- failed query → return safe value  
- null values → resolved deterministically
