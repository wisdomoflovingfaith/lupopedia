# LUPOPEDIA ACTORS COLLECTION

## Index and Guided Reading Order

The Lupopedia Actors Collection is the onboarding library for actors, agents, IDE facets, and authorized human operators working within the Lupopedia Semantic OS.

This page is not a replacement for the constitutional PRDs.

This page is the table of contents that tells each actor:

- what to read
- why the chapter matters
- what must be understood before acting
- which documents apply to a specific role
- where canonical authority lives

Every actor begins with the required reading path.

After completing the required chapters, the actor continues into role-specific, department-specific, and task-specific material.

### Chapter 8 - Dimensional Memory

**Read:**
- docs/actors/dimensional_memory_map.md (indexed; may be missing on disk)
- docs/actors/how_wolves_are_made.md section "Thirteen context vectors" (handbook grid on disk)
- docs/actor_handbook.md (thirteen intersecting vectors)

**Status:**
Read according to the current authority declared in that file.

A proposal remains a proposal until approved through PRD-first governance.

**Boundary (normative):** The thirteen context vectors (WHO through THREAD) are **Actors Collection onboarding vocabulary**. They are **not** automatic approval of a separate "Dimensional Memory System" PRD. Until PRD 84 allocates and a Dimensional Memory PRD is approved, treat Dimensional Memory as proposal-only.

**Purpose:**
Introduces the dimensional context used to evaluate an actor, artifact, message, or memory event.

The dimensional map may include:

- WHO - attributable actor or source
- WHAT - semantic payload or artifact
- WHERE - governed location or route
- WHEN - canonical timestamp
- WHY - rationale, evidence, or causal lineage
- HOW - method or governed process
- DO - available capabilities
- DIRECTIVES - assigned objectives
- FOCUS - active artifacts and context
- DEPARTMENT - formal organizational authority
- DIVISION - registered functional grouping
- CHANNEL - semantic container
- THREAD - scoped task or discussion

**Required outcome:**
The actor can determine whether meaning changes when any relevant dimension changes.

Examples:

- the same words from a different actor may have different authority
- the same instruction in a different department may be invalid
- the same artifact with a different timestamp may be stale
- the same capability without KULEANA may be forbidden
- the same message in a different thread may have different context

**Boundary:**
The dimensional map does not automatically create schema, runtime behavior, or constitutional authority.

Each dimension must be supported by the governing PRDs.
