# TG-4 EdgeValidationService Complete

## File path

- `app/Services/ContextGraph/EdgeValidationService.php`

## Methods implemented

- `validateCreate($sourceType, $sourceId, $targetType, $targetId, $edgeType, $direction, $metadataJson)`
- `validateDelete($edgeId)`
- Internal deterministic helpers:
  - `validateScope(...)`
  - `validateDirection(...)`
  - `validateEdgeType(...)`
  - `edgeExists(...)`
  - `wouldCreateForbiddenCycle(...)`
  - `validateMetadataJson(...)`

## Duplicate detection strategy

- Uses canonical identity generated by `EdgeIdService` + active-row lookup (`is_deleted=0`) in `lupo_context_edges`.
- Rejects duplicate active edges before any mutation call path.

## Cycle detection strategy

- Deterministic bounded traversal (`maxDepth=5`):
  - `dependency`: cycles forbidden
  - `subtask`: cycles forbidden
  - `contradiction`: cycles forbidden (undirected neighbor traversal)
  - `refinement`: cycles allowed
- Contradiction also enforces canonicalized ordering + `direction=both`.

## Unresolved schema friction discovered

- `app/Services/ContextGraph/EdgeService.php` currently defaults to `direction=fwd` for unknown direction and still performs writes directly without invoking `EdgeValidationService` yet.
- Integration hook is still required in TG-3 service to call this validator before `createEdge()` and `deleteEdge()` writes.
