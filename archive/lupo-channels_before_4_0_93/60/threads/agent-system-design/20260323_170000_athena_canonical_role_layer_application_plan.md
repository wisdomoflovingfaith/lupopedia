## 1. System Layer Mapping

| Layer | Definition (doctrine) | Filesystem location | Database table(s) | Session model usage |
|-------|-----------------------|--------------------|--------------------|---------------------|
| **Actor** (role layer) | Stable, doctrine-defined identity that owns a functional domain (builder, strategist, router, critic, talk-story). | `lupo-actors/<actor_slug>/` (e.g., `lupo-actors/hephaestus/`) — contains `.metadata.yaml` and role-specific prompt hierarchy. | `lupo_actors` — one row per canonical actor; columns: `actor_id` (BIGINT, primary key), `slug` (VARCHAR), `name` (VARCHAR), `actor_type = 'role'`, `department_id` (NULL for roles), `is_active`, `is_deleted`, timestamps. | Sessions store `actor_id` (the role) and `faucet_id` (see Faucet model). |
| **Agent** (runtime layer) | Prompt/configuration implementation that realizes an actor's behavior. May be multiple per actor (e.g., different versions). | `lupo-agents/<agent_slug>/` — contains `agent.json`, `capabilities.json`, `system_prompt.txt`. | `lupo_agents` — columns: `agent_id`, `slug`, `actor_id` (FK-style reference, enforced by service), `provider`, `capabilities_json`, `is_active`, timestamps. | Sessions reference the `agent_id` that generated the prompt for a given interaction. |
| **Faucet** (execution surface) | The IDE / tool where an actor's work is performed. Purely a runtime context, not a canonical role. | No dedicated folder; faucet metadata lives in `lupo-actors/<actor_slug>/prompts/faucet/<faucet_slug>/` (e.g., `prompts/faucet/cursor/`). | No dedicated table; faucet information is stored in the session table (`lupo_sessions`) as `faucet_slug` (VARCHAR) and `faucet_version` (VARCHAR). | Each session row includes `faucet_slug` and `faucet_version` to identify the IDE that executed the interaction. |

All three layers are orthogonal; a single interaction is always a tuple **(actor, agent, faucet)**.

## 2. Actor Registry Model

Canonical actors: **HEPHAESTUS, ATHENA, HERMES, LILITH, ROSE**.

Required fields (in `lupo_actors`):

| Field | Type | Notes |
|-------|------|-------|
| `actor_id` | BIGINT | Generated by EdgeIdService (deterministic hash of slug) |
| `slug` | VARCHAR | Lower-case, underscore-only (e.g., `hephaestus`) |
| `name` | VARCHAR | Human-readable title (e.g., `"Builder"`) |
| `actor_type` | VARCHAR | Fixed value `'role'` |
| `department_id` | BIGINT / NULL | NULL — roles are top-level, not department-bound |
| `is_active` | TINYINT | Default `1` |
| `is_deleted` | TINYINT | Default `0` |
| `created_ymdhis` | BIGINT | `gmdate('YmdHis')` UTC |
| `updated_ymdhis` | BIGINT | `gmdate('YmdHis')` UTC |

**Naming conventions:** `slug` must be unique, lower-case, no hyphens, no spaces.

**Identity rules:** once a row is created, `actor_id` and `slug` never change; updates only affect `name` or `is_active`.

## 3. Faucet Model

Faucet identifiers (slug): `cursor`, `windsurf`, `vscode`, `antigravity`.

**Storage:** faucet metadata is not a separate DB table; it lives in session records and in the prompt hierarchy under each actor (`prompts/faucet/<slug>/`).

**Session reference** — `lupo_sessions` (or `lupo_actor_sessions` if a dedicated table exists) includes:

| Field | Type | Notes |
|-------|------|-------|
| `session_id` | PK | |
| `actor_id` | BIGINT | Role |
| `agent_id` | BIGINT | Runtime implementation |
| `faucet_slug` | VARCHAR | e.g., `cursor` |
| `faucet_version` | VARCHAR | Optional build tag |
| `created_ymdhis` | BIGINT | UTC |
| `last_seen_ymdhis` | BIGINT | UTC |

**Routing selection:** When a request arrives, the routing engine (HERMES) looks up the actor from the request context, then selects the faucet based on the client's environment (e.g., HTTP header `X-IDE-Name`). If the header is missing, a default faucet (`cursor`) is used.

## 4. Agent Layer Definition

- **Agent** = concrete implementation of a role's behavior (prompt set, model configuration, capability list).
- **Mapping to actor:** each agent row stores `actor_id` linking it to a canonical role. One role may have many agents (e.g., different model versions).

**Prompt/configuration attachment:**

| Level | Location |
|-------|----------|
| System-level prompt | `prompts/system/base_prompt.md` under the agent folder |
| Department-level overrides | `lupo-actors/<actor_slug>/prompts/department/<dept_slug>/` |
| Faucet-level overrides | `lupo-actors/<actor_slug>/prompts/faucet/<faucet_slug>/` |

**Versioning:** agents are versioned via `agent.json` field `version` (semantic version string). The version is immutable once the agent is activated.

## 5. Migration Plan

### A. Existing System (pre-doctrine)

| Component | Current representation | Where it appears |
|-----------|------------------------|-----------------|
| IDE-named "actors" (e.g., `cursor`, `windsurf`) | Folders under `lupo-actors/` with `.metadata.yaml` containing `actor_id` and `slug`. | Filesystem, `lupo_actors` rows (type `faucet`). |
| Role-related logic | Mixed in the same folders; no clear separation between role and faucet. | Prompt files, channel metadata, session records. |
| Routing tables | Implicit in `lupo_context_edges` (edges from channel → IDE-named node). | DB edge records. |

### B. Migration Strategy

1. **Reclassify IDE-named actors as faucets**
   - Move each IDE folder from `lupo-actors/<slug>/` to `lupo-actors/<canonical_role>/prompts/faucet/<slug>/`.
   - Keep the original `.metadata.yaml` but change `actor_type` to `'faucet'` and set `parent_actor_id` to the corresponding canonical role (to preserve historical linkage).

2. **Create canonical actor entries** (if not already present) in `lupo_actors` for the five roles.

3. **Update session schema** (no DB change yet, just plan) to store `faucet_slug` instead of treating the faucet as an actor.

4. **Adjust routing edges:**
   - Existing edges that pointed to `cursor` etc. are rewritten to point to the canonical role (HEPHAESTUS, ATHENA, etc.) with an additional attribute `via_faucet = '<slug>'`.

5. **Preserve historical data:**
   - Archive the original IDE-actor rows in `lupo_actors_archive` (a read-only table) for audit.
   - Keep the original prompt files as read-only historical artifacts (no deletion).

6. **Documentation update:**
   - Add a migration note in `lupo-docs/doctrine/ACTOR_MODEL.md` describing the reclassification.
   - Tag all migrated files with LUPOPEDIA header `migration_source = 'pre-doctrine'`.

All migration steps are idempotent: running the script twice will detect already-migrated items and skip them.

## 6. Routing Model Update

Routing target is now **always a canonical actor** (`actor_id` from `lupo_actors` where `actor_type='role'`).

Execution surface (faucet) is resolved **after** the actor is selected:

```
Incoming request
  → resolve actor (via channel → role edge)
  → resolve faucet (via request header or default)
  → invoke Agent (agent_id linked to actor)
  → generate response
```

**Edge example** (in `lupo_context_edges`):

| edge_id | source_type | source_id | target_type | target_id | edge_type | metadata_json |
|---------|------------|-----------|-------------|-----------|-----------|---------------|
| 1001 | channel | 58 | actor | `<HEPHAESTUS_id>` | routes_to | `{"via_faucet":"cursor"}` |

The routing engine (HERMES) reads `metadata_json.via_faucet` to select the correct faucet implementation.

| Column | Table | Type | Purpose |
