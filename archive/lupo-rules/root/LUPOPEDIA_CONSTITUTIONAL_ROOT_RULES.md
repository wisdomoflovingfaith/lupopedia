# 🧱 Lupopedia Constitutional Root Rules

**Applies to all IDE agents, external actors, generators, and automated subsystems.**

These rules are absolute, non‑negotiable, and override all module‑level rules.

---

## 🧩 1. Database Doctrine (Absolute)

### 1.1 No Foreign Keys
- No FK constraints.  
- No implicit relational enforcement.  
- All relationships must be explicit in application logic.

### 1.2 No Triggers
- No BEFORE/AFTER triggers.  
- No cascading deletes.  
- No hidden side effects.

### 1.3 No Stored Procedures or Functions
- No logic in the database layer.  
- No vendor‑specific procedural code.

### 1.4 No DATETIME, TIMESTAMP, or vendor time types
- All time must be stored as BIGINT UTC in the format:  
  YYYYMMDDHHIISS  
- Not Unix epoch.  
- Not milliseconds.  
- Not timezone‑dependent.

### 1.5 No AUTO_INCREMENT / SERIAL
- All IDs must be generated by the application layer.  
- Deterministic allocators only (rolling free list, polyphonic allocator, etc.).

### 1.6 Primary Key Naming Rule
Every table's primary key must be named:  
`[tablename_singular]_id`  
Examples: `actor_id`, `decision_id`, `edge_id`, `session_id`

And must be:  
- deterministic  
- BIGINT  
- generated by the application layer  
- never auto‑increment  
- never UUID  
- never random

### 1.7 No vendor‑specific SQL
- SQL must be portable between MySQL and Postgres.  
- No JSON operators, no vendor functions, no dialect tricks.

### 1.8 Database = Dumb Storage
- The DB stores bytes.  
- The application interprets meaning.  
- No hidden logic.  
- No magical behavior.

### 1.9 All INSERT statements must explicitly list all columns
- No implicit column ordering.  
- No lazy inserts.  
- Every column being written must be named.  
- Prevents schema drift and silent breakage.

### 1.10 No implicit defaults except 0 or empty string
- If a column has a default, it must be explicitly defined in doctrine.  
- No DB‑generated defaults.

### 1.11 No Hard Deletes (Soft Delete Only)
- No DELETE statements against canonical tables.  
- All deletions must use:  
  - `is_deleted TINYINT DEFAULT 0`  
  - `created_ymdhis BIGINT`  
  - `updated_ymdhis BIGINT`  
  - `deleted_ymdhis BIGINT DEFAULT 0`  
- Hard deletes allowed only in:  
  - archive tables  
  - scratch tables  
  - maintenance tables  
- Never in lineage tables.

### 1.12 No cascading deletes or updates
- All cascades must be implemented in application logic.  
- Deletion must be explicit, logged, and deterministic.

### 1.13 Database Access Pattern
All DB access must go through `DatabaseFactory::getConnection()` or `lupo_get_db()`.
Never hardcode `lupo_` — always use `LUPO_TABLE_PREFIX`.
Always use prepared statements with named placeholders.

## 🧠 2. Time, Planning, and Scheduling Doctrine

### 2.1 No "weeks", "months", or fuzzy timeframes
- Planning must be state‑based, not calendar‑based.  
- Dependencies define readiness, not dates.

### 2.2 All planning is dependency‑driven
- A task is ready when prerequisites are satisfied.  
- No due dates unless required by external systems.

### 2.3 All time comparisons use BIGINT UTC
- No timezone math.  
- No locale conversions.  
- No human‑friendly date parsing.

### 2.4 Artifact filename timestamps use real UTC only
- Filename timestamps must be generated from real UTC system time only.
- Filename format is `YYYYMMDD_HHIISS`.
- `HH` must be `00-23`, `II` must be `00-59`, and `SS` must be `00-59`.
- No local timezone math.
- No offset arithmetic.
- No guessed or synthetic timestamps.

### 2.4a Markdown headers and IDE-written UTC fields (temporal anchor)
- **`lupopedia.headers`** (`last_modified_utc`, `when_updated`) and **`lupopedia.footer`** (`last_verified`), and new canonical thread filename UTC prefixes, MUST use **real system UTC** via **`python lupo-bin/tick.py`** (and **`python lupo-bin/echo_anchor_utc.py`** to reuse the same batch value)—not LLM-inferred “current time” or copied unrelated timestamps.
- **Binding:** [UTC_TEMPORAL_ANCHOR_DOCTRINE.md](UTC_TEMPORAL_ANCHOR_DOCTRINE.md), [PRD 00 §3.5a](../../lupo-docs/prd/00_root_constitutional_system_requirements.md), [TICK_PY_DOCTRINE.md](../../lupo-docs/doctrine/TICK_PY_DOCTRINE.md).

### 2.5 No human-friendly time parsing by agents
- Agents must not interpret "yesterday", "next week", "3 months ago".  
- Only explicit BIGINT UTC values.

## 🧬 3. Identity & Lineage Doctrine

### 3.1 All entities must have deterministic BIGINT IDs
- No UUIDs.  
- No random IDs.  
- No auto‑generated DB IDs.

### 3.2 All lineage must be explicit
- `parentid`, `rootid`, `depth`, `session_id` must be stored explicitly.  
- No implicit ancestry.

### 3.3 No hidden state transitions
- Every state change must be recorded as an explicit event or decision.

### 3.4 No magical merges or overwrites
- All merges must be explicit and logged.  
- No silent conflict resolution.

### 3.5 No rewriting history
- Historical rows must never be mutated except via explicit, logged updates.  
- No "fixing" old data silently.

## 🧩 4. Application Logic Doctrine

### 4.1 All logic lives in the application layer
- Validation  
- Cascades  
- Referential integrity  
- State transitions  
- Business rules  
- Decision logic  
- All must be implemented in code, not the DB.

### 4.2 All state transitions must be explicit
- No magical updates.  
- No silent mutations.  
- Every change must be traceable.

### 4.3 All agents must produce deterministic output
- No nondeterministic ordering.  
- No random behavior unless explicitly seeded.

### 4.4 No ORM magic
- ORMs may be used only as query builders.  
- No auto‑relations.  
- No auto‑migrations.  
- No lazy loading.  
- No schema inference.

### 4.5 No hidden retries or auto‑recovery
- All retries must be explicit.  
- All failures must be logged.

## 🧱 5. Documentation & Artifact Doctrine

### 5.1 Every module must have a Lupopedia Header
- MODULE  
- CHANNEL  
- TAGS  
- PURPOSE  
- STATUS (planning/development/active)

### 5.2 All agents must respect STATUS
- planning → no migrations, no code generation  
- development → migrations allowed  
- active → read‑only except for patches

### 5.3 All changes require a changelog entry
- No silent edits.  
- No undocumented schema changes.

### 5.4 Canonical artifacts must be deterministic
- No agent may rewrite canonical docs without explicit intent.

### 5.5 Invalid timestamped artifacts are not canonical
- Any artifact filename containing an invalid timestamp is invalid.
- Invalid timestamped artifacts must be blocked from write when validation exists in-path.
- When discovered later, invalid timestamped artifacts must be flagged for explicit correction.
- Validators must never silently normalize invalid timestamps.

- hard deletes

- Validators must reject filename timestamps with `HH > 23`.
- Validators must reject filename timestamps with `II > 59` or `SS > 59`.

### 6.4 All agents must use explicit relationships
- No assumptions  
- No implicit joins  
- No ORM‑inferred relations

### 6.5 All agents must respect lineage
- No rewriting history  
- No collapsing branches  
- No silent pruning

## 🐺 Additional Rules (Lupopedia Specific)

### 9.1 No hardcoded directory names
- All paths must be prefix‑aware and resolved through doctrine.

### 9.2 No triggers, procedures, or foreign keys in migrations
- Migrations must be pure schema changes.  
- No logic allowed.

### 9.3 No schema inference by agents
- Agents must read the schema explicitly before generating SQL.

### 9.4 No silent type coercion
- Agents must not rely on DB coercion (e.g., string → int).  
- All types must be explicit.

### 9.5 No magical "upsert everything" patterns
- UPSERT must be explicit and intentional.  
- No blanket conflict resolution.

### 9.6 PHP 7.4+ Compatibility
- All code must compile on **PHP 7.4** minimum through supported **PHP 8.x**  
- No Composer/outside frameworks not in lupo-includes in the runtime request path  
- No deprecated PHP 8+ syntax that breaks on supported 8.x  
- **Do not** use PHP **8.0+ only** syntax in shared core paths: named arguments, `match`, enums, attributes, `readonly` properties, union types — unless a file is explicitly scoped as modern-only  
- **`??`, `[]`, arrow functions, typed properties, parameter/return types** are allowed where consistent with the file

### 9.7 No Laravel or Middleware Patterns
- No Laravel framework dependencies  
- No middleware patterns  
- No framework magic

### 9.8 Single Install Doctrine
- Only supported upgrade: Crafty Syntax 3.7.5 → Lupopedia 4.0.x  
- No Lupopedia → Lupopedia upgrades  
- Single local instance only

### Release & Migration Doctrine (ABSOLUTE until 4.1.0)

1. **NO database migrations** - All changes require fresh install
2. **NO upgrade paths** - No Lupopedia -> Lupopedia upgrades until 4.1.0
3. **NO ALTER TABLE statements** - Only CREATE TABLE in install_new_lupopedia.sql
4. **NO data preservation** - Existing data is never migrated between versions
5. **ONLY fresh installs** - Each new version starts from empty database
6. **Crafty Syntax ONLY import** - The ONLY allowed data import is from Crafty Syntax 3.7.5 tables
7. **NO migration planning** - Do not waste time on upgrade scripts, data mapping, or version transitions
8. **DELETE and RECREATE** - When schema changes, database is wiped and reinstalled
9. **Focus on clean schema** - All effort goes into correct CREATE statements, not ALTER statements
10. **4.1.0 is the FIRST upgrade** - Before 4.1.0, there are NO production upgrades

### Rationale

Until 4.1.0, Lupopedia is in **active development with breaking schema changes**.
- Every database change requires fresh install
- Development environment only (no production data at risk)
- Crafty Syntax is the ONLY source of importable data
- Migration complexity is deferred to 4.1.0 release

### What This Means For Agents

- **NEVER** write ALTER TABLE statements
- **NEVER** plan data migration strategies  
- **NEVER** worry about preserving existing Lupopedia data
- **ALWAYS** assume fresh install from install.sql
- **ALWAYS** focus on correct CREATE TABLE definitions
- **ONLY** consider Crafty Syntax 3.7.5 → Lupopedia 4.0.x import

### Violation Severity

**CRITICAL** - Any agent proposing migration logic, ALTER TABLE, or upgrade paths is in violation.
