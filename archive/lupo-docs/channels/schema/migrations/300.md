# Migration 3.0.0 — Reserved-Word Column Renames

**Migration Date:** 2026-02-06  
**Migration Type:** One-time development migration (schema alignment)  
**Database Impact:** Column renames only (no new tables, no data migration)  
**Canonical schema:** `lupo-database/migrations/install_new_lupopedia.sql`  
**TOONs:** Not modified; user regenerates after applying migration.

## Summary

Version 3.0.0 renames three columns that conflict with MySQL or PostgreSQL reserved keywords, as identified by the TOON reserved-word audit. A one-time development migration applies the renames to the live database; the canonical install script is updated so new installs use the new column names. PHP code that referenced the renamed columns is updated.

## Column Renames

| Table | Old column | New column | Type (unchanged) |
|-------|------------|------------|------------------|
| `lupo_actor_group_membership` | `role` | `role_key` | varchar(50) DEFAULT 'member' |
| `lupo_artifacts` | `type` | `entity_type` | varchar(64) NOT NULL |
| `lupo_pack_role_registry` | `role` | `role_key` | varchar(255) NOT NULL |

**Note:** `lupo_analytics_paths.year_month` is **not** a reserved word in MySQL or PostgreSQL. The column remains `year_month`; it was incorrectly included in an earlier reserved-word audit and has been reverted. Do not rename it.

## Index Changes

- **lupo_artifacts:** `lupo_artifacts_idx_type` dropped; `lupo_artifacts_idx_entity_type` added on `entity_type`.
- **lupo_pack_role_registry:** `lupo_pack_role_registry_idx_role` dropped; `lupo_pack_role_registry_idx_role_key` added on `role_key`.

## Migration File

- **File:** `lupo-database/migrations/dev_20260206_reserved_word_column_renames.sql`
- **Contents:** ALTER TABLE ... CHANGE COLUMN only; all column names quoted with backticks. No CREATE TABLE, DROP TABLE, foreign keys, or triggers.

## PHP and API Updates

- **lupo-api/v1/artifact.php:** Insert key and SELECT use `entity_type`; response key `entity_type`.
- **lupo-api/v1/timeline.php:** SELECT and response use `entity_type`.
- No other PHP references existed for the renamed columns in `lupo_actor_group_membership` or `lupo_pack_role_registry`. Column `lupo_analytics_paths.year_month` is not a reserved word and was never renamed in code.

## Doctrine and Rules

- **.cursorrules:** Zero Installations / No Backward Compatibility Rule (MANDATORY); Version Lock Rule (3.0.0 until 4.1.0 auto-installer); Pre-Release Version Freeze set to 3.0.0.
- **lupo-docs/doctrine/LUPOPEDIA_DOCTRINE.md:** Fixed version references updated to 3.0.0.
- **Schema and TOON Alignment Rule:** Install is canonical; TOONs are read-only; always quote column names; avoid reserved words.
