# Headers v3 — Implementation & Validation Status Review (2026-04-09)

**Reviewer:** Claude Code (actor 116)
**Scope:** PRD 16, doctrine files in `lupo-docs/doctrine/LUPOPEDIA_HEADERS/`, and
validators `lupo-scripts/validate_lupopedia_headers_universal.py` +
`lupo-scripts/lib/header_validation.py`.

---

## Summary verdict

The **doctrinal specification** (PRD 16 + FORMAT.md) is internally consistent and
well-reasoned. The **validator code has not been updated to match v3** — it still
enforces most of the v2 field set. Every correctly-formed v3 header will currently
fail validation. This is the dominant blocker.

---

## Critical issues (break v3 headers today)

### C-1 — Validator REQUIRED_HEADER_KEYS is v2

**File:** `lupo-scripts/validate_lupopedia_headers_universal.py` lines 26–41

`REQUIRED_HEADER_KEYS` still requires `delegation_chain`, `purpose`, `tags` — all
moved to the sidecar in v3 and explicitly listed as *removed from header YAML* in
FORMAT.md. A valid v3 header (containing none of these) fails with
`[ERROR] missing required header field`.

**Fix:** Replace `REQUIRED_HEADER_KEYS` with the v3 universal set:

```python
REQUIRED_HEADER_KEYS = (
    "header_format_version",
    "lupopedia.schema",
    "when_updated",
    "file_path_from_root",
    "web_path",
    "last_modified_utc",
    "federation_node_id",
    "channel_key",
    "trust_tier",
    "memory_key",
    "artifact_type",
    "artifact_kind",
)
```

Remove the `validate_author_fields()` call from `validate_required_header_fields()`
— author identity is sidecar-only in v3.

---

### C-2 — `lib/header_validation.py` REQUIRED_FIELDS is fully v2

**File:** `lupo-scripts/lib/header_validation.py` lines 38–48

`REQUIRED_FIELDS` mandates `channel_id`, `thread_id`, `actor_id`, `actor_name` —
all deprecated in v3. The `validate_header()` function will produce errors for every
valid v3 header. This lib is imported by other tooling (e.g. the DB sync path).

**Fix:** Gate field requirements on `header_format_version`:

```python
V2_REQUIRED = ("when_updated", "file_path_from_root", "last_modified_utc",
               "channel_id", "thread_id", "actor_id", "actor_name",
               "artifact_type", "artifact_kind")
V3_REQUIRED = ("header_format_version", "lupopedia.schema", "when_updated",
               "file_path_from_root", "web_path", "last_modified_utc",
               "federation_node_id", "channel_key", "trust_tier",
               "memory_key", "artifact_type", "artifact_kind")
```

Select the correct set based on `header.get("header_format_version")`.

---

### C-3 — `memory_key` not validated anywhere

**Files:** `validate_lupopedia_headers_universal.py`, `lib/header_validation.py`

`VALIDATORS_AND_TOOLING.md` (normative) requires validators to:
1. Require `memory_key` field is present.
2. Validate the `.toon` file at that path exists.
3. Validate the memory file path matches trust-tier pattern.
4. Validate the memory file payload contains required fields.

None of these checks are implemented. `validate_memory_file_exists.py` (listed in
VALIDATORS_AND_TOOLING.md as a dedicated entrypoint) does not exist.

**Fix:** Add a `validate_memory_key()` function to the universal validator:
- Check `memory_key` is present and non-empty.
- Check the `.toon` file exists on disk.
- Check path conforms to trust-tier pattern:
  - `seed`: `lupo-memory/{channel_key}/seed/{slug}.toon`
  - `canonical`: `lupo-memory/{channel_key}/canonical/{display_year}/{month}/{slug}.toon`
  - `staging`: `lupo-memory/{channel_key}/staging/{year}/{month}/{slug}.toon`
- Optionally parse and validate required sidecar fields (`id`, `type`, `purpose`,
  `status`, `tags`, `author`, `footer`) — warn if missing, do not hard-fail during
  migration window.

Create `lupo-scripts/validate_memory_file_exists.py` as a batch wrapper.

### C-4 — DETERMINISTIC_FIELD_ORDER contains v2 fields

**File:** `validate_lupopedia_headers_universal.py` lines 44–69

The field order list includes `channel_id`, `actor_id`, `actor_name`,
`delegation_chain` — not present in v3 headers. v3 files will trigger
`[ERROR] Fields not in deterministic order` because v3-specific fields
(`channel_key`, `trust_tier`, `memory_key`) appear as "unknown fields".

**Fix:** Define a v3 field order and branch on `header_format_version`:

```python
DETERMINISTIC_FIELD_ORDER_V3 = [

    "file_path_from_root",
    "web_path",
    "last_modified_utc",
    "federation_node_id",
    "channel_key",
    "trust_tier",
    "memory_key",
    "artifact_type",
    "artifact_kind",
    # Conditional fields (PRDs)
    "thread_id",
    "prd_id",
    "prd_slug",
    "title",
    "status",
    "parent_prd",
    "version",
    "dialog_transcript",
]
```

### C-5 — `prd` schema missing from VALID_SCHEMA_VALUES and DEPENDENCY_MAP

**File:** `validate_lupopedia_headers_universal.py` lines 98–103, 119–187

PRD 16 itself uses `lupopedia.schema: prd`. The validator will emit
`[WARN] 'prd' is not a standard schema value` and then fail cross-field validation
because there is no entry in `DEPENDENCY_MAP` for `prd`.

**Fix:** Add `prd` to `VALID_SCHEMA_VALUES`:

```python
VALID_SCHEMA_VALUES = [
    'prd', 'doctrine', 'rule', ...
]
```

Add to `DEPENDENCY_MAP`:

```python
'prd': {
    'artifact_type': ['prd'],
    'artifact_kind': ['requirements', 'architecture', 'specification'],
},
```

## Major issues (break specific scenarios or cause silent misvalidation)

### M-1 — `channel_key` vs `channel_id` for discussion type

**File:** `validate_lupopedia_headers_universal.py` lines 488–497

`validate_required_fields_by_type()` for `artifact_type: discussion` still requires
`channel_id` (numeric). v3 uses `channel_key` (string slug). Discussion artifacts
created to v3 spec will fail; v2 discussions will spuriously pass.

**Fix:** Change to require `channel_key` for v3 headers, keeping `channel_id` check
only for v2 (`header_format_version < 3`).

---

### M-2 — `implementation` kind `README` incorrectly requires `version`

**File:** `validate_lupopedia_headers_universal.py` lines 507–517

The validator requires `['parent_prd', 'status', 'version']` for ALL implementation
kinds. PRD 16 table (Conditional Required Fields) only requires `version` for
`implementation/documentation`; `implementation/README` needs only `parent_prd` +
`status`.

**Fix:** Branch by `artifact_kind`:

```python
if artifact_kind == 'README':
    required = ['parent_prd', 'status']
elif artifact_kind == 'documentation':
    required = ['parent_prd', 'status', 'version']
else:
    required = ['parent_prd', 'status']
```

---

### M-3 — `prd_slug` regex rejects hyphens

**File:** `validate_lupopedia_headers_universal.py` line 478

Validator requires `^[a-z][a-z0-9_]*$` (underscores only). PRD 16's own example
shows `prd_slug: lupopedia-headers` (hyphens). Every existing PRD with a
hyphenated slug will fail.

**Fix:** Change to `^[a-z][a-z0-9_-]*$` (allow hyphens).

---

### M-4 — `memory_key` path format divergence in doctrine files

**Files:** `VALIDATORS_AND_TOOLING.md`, `VERIFICATION_GUIDE.md`

These files carry `memory_key` values that do not follow the trust-tier pattern
defined in FORMAT.md and PRD 16:

- `VALIDATORS_AND_TOOLING.md`: `lupo-memory/2026/04/M-lupopedia-headers-validators-20260409.toon`
- `VERIFICATION_GUIDE.md`: `lupo-memory/2026/04/M-lupopedia-headers-verification-20260409.toon`

The canonical pattern for `canonical` tier is:
`lupo-memory/{channel_key}/canonical/{display_year}/{month}/{slug}.toon`
(display_year = actual_year - 1000)

Both files use actual year 2026 (not display year 1026), omit channel_key, and omit
trust tier directory. These would fail any `memory_key` path validator.

**Fix:** Update those headers to use conformant paths, e.g.:
`lupo-memory/development/canonical/1026/04/lupopedia-headers-validators.toon`

---

### N-2 — `validate_author_fields` should be no-op for v3

**File:** `validate_lupopedia_headers_universal.py` lines 536–561

For v3, author lives in the sidecar. The current code returns `[ERROR] missing
author attribution` if the header has no `author` block and no legacy
`actor_id`/`actor_name`. Since v3 headers legitimately lack all of these, this
produces a false error.

After C-1 is fixed (removing `validate_author_fields` from the v3 path), also
ensure legacy v2 migration path still validates author for v2 format files.

---

### N-3 — `validate_tag_prefixing` fires on v3 headers

`tags` is not present in v3 headers (sidecar-only). The tag prefixing validator
currently warns if `tags` is empty. For v3, the absence of `tags` in header YAML is
correct; the check should be skipped or treated as valid.

---

### N-4 — `check_staleness` reads `last_verified` from YAML header

For v3, `last_verified` is in the sidecar, not in YAML. The staleness regex check
(`re.search(r'last_verified:\s*"?(\d{8,14})"?', content)`) will silently produce no
warning for stale v3 files. Staleness checks for v3 need to read the `.toon` sidecar
via `memory_key`.

---

### N-5 — `validate_yaml_file` calls `validate_thread_id_format` unconditionally

`thread_id` is conditional in v3 (required only for discussion/thread artifacts).
The unconditional call at line 1056 will emit `[ERROR] thread_id missing` for every
non-thread v3 artifact, which is incorrect.

**Fix:** Guard the call:

```python
if hdr.get('artifact_type') in ('discussion',) or hdr.get('thread_id') is not None:
    if not validate_thread_id_format(hdr.get("thread_id"), file_path):
        return False, None
```
