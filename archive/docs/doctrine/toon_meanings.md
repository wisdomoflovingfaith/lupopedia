# Lupopedia Memory TOON (structured sidecar metadata document — NOT a cartoon)

## TOON meanings doctrine

**Captain's Log — 2026-04-18**  
**Doctrine file:** `toon_meanings.md` (also searchable as TOON_meanings)  
**Trust tier:** canonical  
**Scope:** Memory system, schema exports, LLM or agent prompts, orchestration, and tooling

## Purpose

This document is the single source of truth for the term **TOON** inside Lupopedia. It removes ambiguity so models and humans do not default to the public pun meaning (“toon = cartoon”).

## Official definitions

### 1. TOON-M — Memory sidecar (default meaning)

- **Full name:** Lupopedia Memory TOON  
- **File extension:** `.toon`  
- **Location:** `memory/...`  
- **Purpose:** Structured metadata sidecar for development memory, doctrine, handoff checkpoints, and semantic graph edges.  
- **Shape:** JSON-shaped document (often generated by `generate_memory_from_header.py`) with `edges`, `header_bridge`, `purpose`, and related fields; Markdown-first handoffs may live beside or under the same naming discipline until normalized.  
- **Key characteristic:** Human- and agent-readable memory artifact tied to headers via `memory_toon`.  
- **Default rule:** When “TOON”, “toon”, or “`.toon`” appears **without qualifier**, interpret as **TOON-M** unless context forces TOON-S or TOON-W.

**Mandatory disambiguation line (verbatim) in every TOON-M surface when authoring prose headers or first lines:**

`# Lupopedia Memory TOON (structured sidecar metadata document — NOT a cartoon)`

### 2. TOON-S — Schema export

- **Full name:** TOON schema export  
- **File extension:** Usually `*.toon.json`  
- **Location:** `database/lupopedia/toon/` (and regenerated companions under `docs/toons/` per release process)  
- **Purpose:** Generated column dictionaries and table-shape mirrors from canonical install SQL — agents read columns from exports, not from guesses.  
- **Key characteristic:** Machine-generated, reviewable schema representation.  
- **Rule:** Say **TOON-S** or “schema TOON export” when you mean this path; do not call it a memory handoff.

### 3. TOON-W — Token-Oriented Object Notation (wire format)

- **Full name:** Token-Oriented Object Notation  
- **Purpose:** Compact encoding for structured data **at the LLM prompt boundary**.  
- **Usage:** Encode/decode around prompts and agent harnesses; **do not** treat production on-disk doctrine or authoritative rows as TOON-W unless a written exception exists.  
- **Key characteristic:** Fewer tokens than equivalent JSON for repetitive tabular shapes.  
- **Tooling:** Off-core scripts or operator tooling only (for example JS `encode`/`decode` packages); **never** wire npm packages into `includes` bootstrap.

## Usage rules (enforced doctrine)

1. Unqualified “TOON” / “`.toon`” → **TOON-M** (memory sidecar) unless context explicitly names TOON-S or TOON-W.  
2. **TOON-W** only when discussing LLM wire format, prompt compaction, or harness boundaries.  
3. **TOON-S** only when discussing schema exports from the database / install SQL mirror tree.  
4. Every **TOON-M** file **SHOULD** carry the mandatory disambiguation line (above) and graph hooks; at minimum include **one** `disambiguates` edge toward cartoon confusion when emitting `edges.outbound`.  
5. Mixing the three meanings in prose, paths, or headers is a **doctrine violation** — fix the word choice or the path before merge.
