# Castcade Metadata Handling Checklist

## Purpose

This checklist provides operational guidance for Castcade and other agents when working with Lupopedia's three-layer metadata system (headers, metadata, footers).

## Quick Reference

| Layer | Purpose | When to Use | Key Rules |
|-------|---------|-------------|-----------|
| **Headers** | File identity | File creation/identity updates | Only 22 canonical fields |
| **Metadata** | Contextual notes | Section-specific annotations | Keep local, preserve position |
| **Footers** | Operational tasks | Pending work, agent notes | Flexible, task-oriented |

---

## 🟥 Headers - Identity Layer

### ✅ DO:
- Use only the 22 canonical fields from PRD 16 §4.2
- Maintain deterministic field ordering
- Update `when_updated` when file changes
- Validate with universal validator
- Keep headers clean and identity-focused

### ❌ DO NOT:
- Add operational fields (orchestrator, next_action)
- Include comments or notes
- Mix with other metadata types
- Invent new fields
- Place task lists in headers

### 📝 Common Operations:
```yaml
# Updating timestamp
when_updated: "20260420050000"

# Changing status
status: "complete"

# Updating thread reference
thread_id: "new-thread-id"
```

---

## 🟦 Metadata - Contextual Layer

### ✅ DO:
- Place near relevant content
- Keep section-specific and local
- Preserve existing metadata blocks
- Use for semantic annotations
- Add comments about specific paragraphs

### ❌ DO NOT:
- Move to headers or footers
- Treat as global file metadata
- Assume it applies to entire file
- Validate or normalize structure
- Remove without understanding context

### 📝 Common Operations:
```yaml
---
lupopedia.metadata:
  comments:
    - "This paragraph introduces the emotional pivot."
  notes:
    - "Check lineage consistency for this section."
  context:
    - "References PRD 07 section 3.2"
---
```

### 🎯 Placement Guidelines:
- **Before** the content it describes
- **After** a section header for section-wide notes
- **Between** paragraphs for specific line comments
- **Never** in headers or footers

---

## 🟩 Footers - Operational Layer

### ✅ DO:
- Add pending edges and references
- Include next actions and tasks
- Add agent notes and warnings
- Update existing footer blocks
- Remove resolved items

### ❌ DO NOT:
- Treat as canonical metadata
- Validate field structure
- Enforce deterministic ordering
- Assume every file has a footer
- Mix with identity metadata

### 📝 Common Operations:
```yaml
---
lupopedia.footer:
  pending_edges:
    - to: "some/file.md"
      reason: "Referenced in text but not linked"
  next_actions:
    - "Review this file for missing lineage"
    - "Add examples to section 3"
  comments:
    - "Script detected inconsistent naming"
    - "Generated by enqueue_files.py v1.2"
---
```

## 🔍 Detection Patterns

### Header Pollution (Fix Required)
```yaml
# WRONG - These belong elsewhere
lupopedia.headers:
  # ... canonical fields ...
  orchestrator: "wolfie:root"      # Move to metadata or remove
  next_action:                     # Move to footer
    - "Fix this file"
  comments:                        # Move to metadata/footer
    - "This needs review"
```

### Misplaced Metadata (Fix Required)
```yaml
# WRONG - Metadata in header
lupopedia.headers:
  # ... canonical fields ...
  metadata:                        # Should be separate block
    comments: ["..."]
```

### Correct Structure
```yaml
---
lupopedia.headers:
  # Only 22 canonical fields
---

# Content here

---
lupopedia.metadata:
  # Contextual annotations (optional)
---

# More content

---
lupopedia.footer:
  # Operational tasks (optional)
---
```

## 📋 Validation Checklist

### Before Saving Changes:
- [ ] Headers contain only canonical fields
- [ ] Metadata blocks are properly positioned
- [ ] Footer content is task-oriented
- [ ] No layer mixing or pollution
- [ ] Field ordering follows PRD 16

### After Making Changes:
- [ ] Run universal validator on headers
- [ ] Check for orphaned metadata blocks
- [ ] Verify footer structure is clean
- [ ] Test file parsing and rendering
- [ ] Update related references if needed

---

## 🚨 Common Mistakes to Avoid

1. **Header Pollution**
   - Adding operational fields to headers
   - Mixing metadata types in header block
   - Inventing non-canonical fields

2. **Metadata Misplacement**
   - Putting metadata in headers
   - Moving metadata away from its content
   - Treating local metadata as global

3. **Footer Abuse**
   - Putting identity data in footers
   - Over-validating footer structure
   - Assuming every file needs a footer

4. **Layer Confusion**
   - Not understanding which layer to use
   - Mixing purposes between layers
   - Ignoring semantic boundaries

---

## 🎯 One-Sentence Rules

- **Headers**: Only the 22 canonical fields, nothing else.
- **Metadata**: Local to content, stay where placed.
- **Footers**: Tasks and notes, flexible structure.

## Summary

By following this checklist, Castcade and other agents can properly handle Lupopedia's metadata system without corrupting file identity, losing contextual information, or polluting operational workspaces. The key is to always ask: **"What type of information am I storing?"** and use the appropriate layer.
