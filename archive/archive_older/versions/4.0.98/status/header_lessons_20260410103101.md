# Status: Lessons Learned on Legacy Lupopedia Headers

Generated: 2026-04-10 10:37:15 UTC
Actor: Cursor IDE (102)

## What I Learned

- Legacy header blocks can be structurally valid for their era but violate current PRD 16 expectations when mixed with new fields.
- Upgrading old headers is safer when done as a clean rewrite of the `lupopedia.headers` block instead of piecemeal edits.
- For current doctrine files, keep frontmatter compact and avoid bloating it with optional blocks when a short header is required.
- Deprecated keys (`channel_id`, `when_updated_utc`) should be removed rather than translated in-place unless a migration spec requires both.
- Modern minimum set should include `header_format_version`, identity/path fields, and current routing fields (`channel_key`, `trust_tier`, `memory_key`) in deterministic order.
- Header line-count constraints must be treated as a hard acceptance criterion before finalizing edits.
- For TOON authoring workflow, keep TOON as canonical and generate JSON from TOON when compatibility fallback is needed.

## Operational Rule Going Forward

When remaking old headers:
1. Copy file content below frontmatter to a temporary buffer.
2. Replace the entire frontmatter with a fresh, minimal compliant header.
3. Reinsert body unchanged.
4. Re-check line-count and deprecated key absence before completion.
5. For memory/serialization artifacts, author TOON as source of truth and generate JSON sidecars from TOON instead of hand-maintaining both formats.
