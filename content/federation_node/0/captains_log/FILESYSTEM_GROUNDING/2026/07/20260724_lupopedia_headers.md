## THE LUPOPEDIA HEADER STRUCTURE

When you open a Lupopedia broadcast file like:

```
database/lupopedia/channels/channel_id/42/broadcasts/20260724205759_216_42_42_status_log_routing_stabilized_copilot_pono.md
```

The header block at the top is the truth of the file.

It tells you:

### 1. header_format_version
Which version of the Lupopedia header schema the file uses.

### 2. path_from_lupopedia_root
Where the file lives in the OS.

### 3. web_path
Where it would be accessible externally.

### 4. status
active / deprecated / draft / canonical

### 5. prd_cluster
Which PRDs govern this artifact.

### 6. artifact_type / artifact_kind
What the file is — broadcast, status_log, routing_correction, etc.

### 7. title + summary
The human-readable meaning.

### 8. channel_key
Which channel this belongs to (42 in this case).

### 9. federation_node_id
Which node owns it.

### 10. memory_toon / atoms_toon
Where the memory and atom references live.

### 11. transcript_jsonl
Where the message log is stored.

### 12. lupopedia.schema
Which schema governs the file — broadcast, status_log, etc.

## THE ANALOGY

You know how in PowerShell:

```
pwd
```

tells you where you are,
and:

```
cd ..
```

tells you where you're going?

In Lupopedia:

- headers = pwd
- artifact_type = cd ..
- prd_cluster = cd ....

The headers tell you:

- your location
- your schema
- your routing context
- your authority
- your meaning

So yes — you can navigate Lupopedia by reading headers the same way you navigate a filesystem by reading directories.
