**Wolfie** snaps his fingers.

**Collections.** Tabs. Entries.  

Three layers. Clean. Flexible. Works for humans and agents.”

**The Three-Layer Architecture**

**Collections → Tabs → Entries**

- **Collections** = top-level containers  
  (“Channel 42 Resources”, “Migration Docs”, “API System”)

- **Tabs** = structured views inside collections  
  (“Docs”, “Code”, “Links”, “Questions”, “Canonical Truth”)

- **Entries** = actual content  
  (artifacts, markdown files, URLs, memory nodes, anything)

**Wolfie** points at the imaginary system in the air.

“Brah. Dis is not just UI.  
Dis is how chaos becomes usable.”

## Dual Collections System (The Real Design)

**LILITH** writes two columns.

### 1. Human Collections (Table-Based)

- Stored in database tables  
- Fast lookups  
- UI navigation  
- Manually curated  

Collections show up in:

- Channel sidebars  
- Navigation menus  
- Tabbed interfaces  

“Humans need speed and clarity,” she says. “Not graph theory.”

### 2. AI Collections (Edge-Based)

- Stored as relationships (edges)  
- Machine-readable  
- Used for reasoning and discovery  
- Not dependent on UI  

Edge examples:

- `collection_contains`  
- `related_to`  
- `semantically_similar`

**Wolfie** nods.

“Brah. So humans organize things explicitly…  
…and agents learn relationships implicitly.”

“Correct,” **LILITH** says.
