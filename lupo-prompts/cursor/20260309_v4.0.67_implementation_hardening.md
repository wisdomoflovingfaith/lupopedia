1. latest actual legacy message timestamp linked to the thread if available
2. transcript or update timestamp if available
3. null only when no usable timing source exists

### Constraints

- inspect the real legacy source columns before changing SQL
- do not invent legacy columns that are not really in the import source

- if existing imported rows also need cleanup, add a narrowly scoped migration only if justified by actual repo conventions

### Verification

- confirm no insert or column-count regressions were introduced
