## 2. Database Doctrine (Non-Negotiable)

You **must** obey these rules for any schema or SQL you touch:

| Rule | Meaning |
|------|--------|
| **No foreign keys** | No `FOREIGN KEY`, no `REFERENCES`. Relationships are in application code only. |
| **No triggers** | No `TRIGGER` definitions. |
| **No stored procedures / functions** | No `PROCEDURE`, no stored `FUNCTION`. |
| **Timestamps** | All date/time columns are **SIGNED BIGINT** in **UTC `YYYYMMDDHHIISS`** (e.g. `20260308120000`). Set in PHP with `gmdate('YmdHis')`. **No** `DATETIME`, **no** `TIMESTAMP`, no epoch seconds. |
| **Integer types** | `BIGINT`, `INT`, `SMALLINT`, `TINYINT` only. No display widths (e.g. no `BIGINT(14)`), no `UNSIGNED`, no `BOOLEAN`. |
| **Soft deletes** | Tables that hold user/system data use `is_deleted TINYINT DEFAULT 0` and `deleted_ymdhis BIGINT DEFAULT 0`; queries must filter `WHERE is_deleted = 0` by default. |
| **Table prefix** | Never hardcode `lupo_`. Use `LUPO_TABLE_PREFIX` (from config). |
| **Primary keys** | Named `<table_singular>_id` (e.g. `actor_id`, `dialog_message_id`). No generic `id`. |
| **Reserved IDs** | Actor IDs 0–9999 reserved for AI/system; human actors start at 10000. Registry-backed tables do **not** use AUTO_INCREMENT; application supplies explicit IDs. |

**References:**  
- `AGENTS.md` — Critical Doctrines (Database Rules, Timestamp Rules, Schema Source of Truth).  
- `docs/doctrine/ACTOR_REQUIREMENTS.md` — LUPO database doctrine (no FKs, triggers, procedures, functions, DATETIME/TIMESTAMP).  
- `.cursor/rules/` — toon-source-of-truth, database-logic-prohibition-doctrine, pk-reference-naming-doctrine, php-5-3-compatibility, pdo-db-database-access-doctrine, reserved-id-doctrine.
