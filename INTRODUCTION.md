# WHAT LUPOPEDIA IS — THE COMPREHENSIVE EXPLANATION

Based on research of the README and 10+ PRD files, here is what Lupopedia actually is:

## The Core Concept

Lupopedia is a **constitutional semantic operating system** built as the successor to Crafty Syntax 3.7.5 — a live-chat system that has been running for 20+ years with ~23,000 installations. It's not just another AI tool or framework — it's a radical rethinking of how documentation, AI agents, and software systems should interact.

## The Fundamental Philosophy

The premise is: "Documentation should be executable law. AI should follow constitutions, not vibes."

Instead of AI agents guessing or inferring behavior from training data, Lupopedia creates a constitutional architecture where:
- PRDs (Product Requirements Documents) are the primary source of truth
- Doctrine files explain and expand PRDs
- AI agents are constitutionally bound to follow written rules
- WHY files document every violation and create a self-healing system

## Key Architectural Concepts

### 1. PRD-First System
- 100 PRD groups (00-99) with sub-PRDs (A-Z)
- `prd_cluster` strings define exact reading order (e.g., `00_A-i_16_C-i`)
- PRDs are read sequentially, not conceptually — the first PRD kills model priors
- No code can be written until PRDs exist and are correct

### 2. Three-Layer Identity Model
- **Auth User**: Human login/authentication (`lupo_auth_users`)
- **Actor**: Runtime persona that does work (`lupo_actors`) — department-scoped
- **Agent**: Immutable template/blueprint (filesystem-based)

Critical distinction: Agents don't learn, Actors do. Many humans can act as the same Actor within a department.

### 3. Constitutional Database Rules
- No database logic: No foreign keys, triggers, stored procedures, or functions
- No AUTO_INCREMENT: All IDs generated by application-layer `IdGenerator::generate()`
- Packed UTC timestamps: All timestamps are BIGINT in YYYYMMDDHHIISS format
- Database-neutral SQL: Works on MySQL 8.0+ and PostgreSQL 15+
- Shared hosting compatibility: No server-level dependencies or configuration changes

### 4. LUPOPEDIA HEADERS System
- Every authored file has a 22-field header with identity, routing, and memory linkage
- `header_format_version: "4.1.7"` is currently frozen
- Headers provide deterministic lineage and reproducibility
- ASCII-only doctrine enforced (no emoji, Unicode arrows, smart quotes)

### 5. AGAPE Resilience Framework
- Self-healing system that turns violations into learning opportunities
- WHY files automatically document violations in `docs/why/`
- Causal chain reconstruction required before any action: INTENT, WHO, WHAT, WHERE, WHEN, HOW
- Fallback ladders for graceful degradation when actors stall
- No heartbeat polling — only tracks `when_updated` timestamps

### 6. Versioning Doctrine
- **4.0.x**: Bootstrap phase (Crafty Syntax 3.7.5 → Lupopedia)
- **4.1.x**: Active development phase (breaking changes allowed)
- **4.2.0**: Stable baseline (first version with guaranteed upgrade paths)
- No Lupopedia→Lupopedia upgrades until 4.2.0 — fresh installs only before then

### 7. File System vs Database Separation
- Database: Indexes, metadata, relationships only
- File System: Content, memory nodes, TOON files, transcripts
- Rule: If it's bigger than 255 chars, it goes in the file system

### 8. TOON (Token-Oriented Object Notation)
- AI-native data format that reduces token usage by ~50% compared to JSON
- Canonical, immutable, read-only serialization layer
- Used for memory, registry, and schema artifacts

## Why This Matters

Lupopedia solves the fundamental problem of documentation drift and AI hallucination:
- **Deterministic behavior**: Rules are written down first, then followed
- **Self-healing**: Every violation strengthens the system via WHY files
- **Multi-agent coordination**: 11 primary personas (WOLFIE, LILITH, ANUBIS, etc.) with specialized roles
- **Channel-based collaboration**: All work happens in channels with thread-scoped execution
- **Budget survival**: $50/month token budget with free-tier-first provider chaining

## The Big Picture

Lupopedia is essentially a "Semantic OS" where:
- Documentation is executable law
- AI agents follow constitutions, not statistical patterns
- Every mistake becomes a teaching moment
- The system gets stronger and smarter over time
- It's designed to survive on shared hosting with minimal dependencies

It's the result of 20+ years of maintaining Crafty Syntax, realizing that the real problem wasn't the code, but that nobody was writing down the rules in a way AI (or even future humans) could reliably follow.

The system is currently at version 4.1.7 and is being actively developed by Eric Robin Gerdes (Captain WOLFIE), with the goal of reaching the stable 4.2.0 baseline that will support auto-installer distribution and guaranteed upgrade paths.

## What Is Lupopedia?

Lupopedia is a **doctrine-driven semantic operating system** and multi-agent platform that evolves the **Crafty Syntax 3.7.5** lineage into a constitutional architecture for modern orchestration, truth management, and channel-based collaboration.

### Core Architecture Principles

**1. Documentation as Executable Law**
- PRDs are not passive specifications—they are the actual source of truth
- Every component must follow written rules contained in PRD files
- When something breaks, we update the constitution, not just patch the code

**2. Constitutional Multi-Agent Governance**
- Multiple specialized agents (WOLFIE, LILITH, AGAPE, HERMES, etc.) work within explicit boundaries
- Each agent has specific responsibilities, limitations, and accountability mechanisms
- Agents are constitutionally bound to follow explicit rules, not statistical guessing

**3. Truth Management Over Data Management**
- Focus on maintaining truth rather than just storing and retrieving data

### The Four-Axis PRD System

Lupopedia uses a sophisticated documentation architecture where PRDs reference other PRDs, forming clusters that define behavior, truth, limits, and system identity through:

- **Positional Priority** (array index = reading order)
- **Significance Weight** (A–F letter)
- **Grouping** (numeric category)
- **Chronology** (Roman numeral = time created)

Each file carries a header that records the exact `prd_cluster`, the full `transcript_jsonl` dialog, and `atoms_toon` for canonical truth, ensuring deterministic lineage and reproducibility.

**PRD 26: Five-Layer Documentation Architecture**

**PRD 57: AGAPE Resilience Doctrine**

**PRD 98: WHY Files Doctrine**
