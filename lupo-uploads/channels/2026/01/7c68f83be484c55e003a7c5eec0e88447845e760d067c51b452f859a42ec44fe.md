## Database Doctrine

All contributors must understand Lupopedia's pure data store approach.
See **WHY_LUPOPEDIA_USES_PURE_DATA_STORE.md** for complete reasoning on:

- Why triggers destroy data merging
- How foreign keys break orphan handling  
- Why stored procedures break federation
- How soft delete requires temporary invalid states
- Why probabilistic cleanup needs full control
- How doctrine requires deterministic behavior

## Programmer Competency Doctrine

All contributors must meet the requirements defined in
GOV-PROGRAMMERS-001.md. These include:

- Foundational knowledge equivalent to a 2000-era BS in Computer Science
- Mastery of data structures, algorithms, and memory fundamentals
- Understanding of operating systems, networking, and database theory
- Ability to program without frameworks or AI assistance
- Ability to reason about architecture and schema
- Ability to follow doctrine and maintain system integrity

## Testing Requirement

All contributors will be tested in person by the system architect
(Eric Robin Gerdes) to verify competency before contributing to the system.

## Certification Process

Candidates must complete the **PROGRAMMER_CERTIFICATION_CHECKLIST.md** which includes:

- Foundational computer science verification
- Systems knowledge assessment  
- Programming ability evaluation
- Lupopedia-specific requirements
- Database doctrine compliance
- In-person evaluation by system architect

All items must be satisfied before granting access to development channels, schema, migrations, or system‑level code.
