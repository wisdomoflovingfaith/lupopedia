## Conceptual Improvements

1. Defined Lupopedia clearly as a semantic operating system rather than a generic chat, ticket, or graph product.

3. Explained why channels, threads, and dialog are central: durable work context and human coordination inherited from Crafty Syntax.
4. Added the corrected actor/auth_user explanation from Thread 2011: many-to-many support pools, primary routing, and transitional status of `lupo_actors.auth_user_id`.
5. Added the routing MVP reality from Thread 2012: implemented, corrected, deterministic, and COMPLIANT, but still MVP scope.
6. Added the explicit install-readiness outcome from Thread 2013 so the system is described as validated for the current install/reset cycle, not only as schema-correct and authority-correct.
7. Made the database/filesystem duality explicit instead of treating one side as a metaphor for the other.
8. Explained why version directories replaced a flat changelog for 4.0.85+.
9. Marked Doom Emacs influence correctly as research-only conceptual input, not accepted schema implementation.
10. Marked dialog correctly as foundational and operational in parts, but not a finished web UI.

## How the Rewrite Reflects Current System Reality

### What is already real
- channels, threads, and filesystem artifacts are active coordination surfaces
- install SQL is canonical schema authority
- TOONs are derived and synchronized to install SQL
- actor/auth_user support pools are corrected and valid for routing
- routing MVP is implemented and COMPLIANT
- Thread 2013 explicitly validated install readiness with a dual PASS verdict
- external AI and IDE faucets participate through filesystem-readable doctrine and artifacts

### What is not overstated
- Doom Emacs research is not presented as finished implementation
- decision lineage PHP behavior is not described as complete
- dialog is not described as a finished web interface
- version overviews are not presented as replacing TASK_REGISTRY authority

### Why the rewrite matters
The old overview surfaces described many correct ideas, but they did not clearly separate:
- lineage from implementation
- schema from research
- task authority from overview prose
- actor identity from auth identity
- foundational dialog infrastructure from completed user-facing dialog UI

This rewrite corrects those boundaries so both humans and IDE agents can reason about the system without being forced to infer architectural truth from scattered thread artifacts.
