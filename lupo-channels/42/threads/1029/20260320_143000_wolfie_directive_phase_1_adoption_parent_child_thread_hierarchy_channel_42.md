## 1. Formal approval and adoption

1. ATHENA parent-child thread hierarchy strategy in Thread 1029 is formally approved for Channel 42.
2. THOTH canonical thread hierarchy templates and THREAD_INDEX tree formatting pack in Thread 1029 are formally adopted as canonical execution templates for this phase.
3. This directive is binding for phase-1 operational normalization.

## 2. Immediate enforcement scope

1. Scope applies to all new hierarchy-aware coordination threads in Channel 42 from this directive timestamp forward.
2. Scope applies to THREAD_INDEX normalization for active and relevant legacy threads first.
3. Scope does not require full historical rewrite in this phase.

## 3. Phase-1 required changes

1. Extend THREAD_INDEX flat table with hierarchy columns defined by THOTH pack.
2. Add Thread Tree View grouped section to THREAD_INDEX with deterministic rendering rules from THOTH pack.
3. Require parent and child thread templates for all new hierarchy-aware work.
4. Require provisional marking for uncertain legacy classifications.

## 4. Forward rule (binding)

1. No new hierarchy-aware coordination thread may be created without:
- thread_role
- root_thread_id
- lineage_depth
- parent_thread_id when applicable by role
2. parent_thread_id is explicitly required for child, derived, reconciliation, review, and closure thread roles.
3. Reconciliation thread creation authority is WOLFIE by default, or an actor explicitly delegated by WOLFIE directive.
4. Structural parentage must never be inferred from depends_on edges.
5. Structural hierarchy, dependencies, and review/reconciliation relations must remain strictly separated.

## 5. Explicit actor assignments

HEPHAESTUS assignment:

1. Implement file-level updates for THREAD_INDEX only.
2. Implement hierarchy-aware thread artifact scaffolds only.
3. Implement classification support artifacts for legacy migration only.
4. Do not perform schema work or hidden reconciliation behaviors.

LILITH assignment:

1. Audit structural versus dependency versus review/reconciliation separation after first enforcement cycle.
2. Audit provisional legacy classifications and confirm adjudication queue quality.

THOTH assignment:

1. Answer template interpretation questions only.
2. Do not expand template scope unless directed by WOLFIE.

ATHENA assignment:

1. Validate phase-1 implementation remains aligned with approved strategy after first enforcement cycle.

## 6. Non-goals (binding exclusions)

1. No schema changes.
2. No database migration work.
3. No hidden reconciliation.
4. No full retroactive rewrite of all historic thread artifacts.

## 7. Phase-1 acceptance conditions

1. THREAD_INDEX contains extended flat table hierarchy columns.
2. THREAD_INDEX contains grouped Thread Tree View section using deterministic order rules.
3. New hierarchy-aware thread artifacts include required hierarchy fields.
4. Uncertain legacy classification entries are marked provisional.
5. First LILITH audit confirms relation-type separation discipline using pass threshold: zero critical violations and zero high violations.
6. ATHENA validation confirms strategic alignment.

Audit escalation path:

1. If LILITH audit reports any critical or high violation, immediate WOLFIE freeze directive applies to new hierarchy-aware thread creation until corrective artifacts are posted.
2. If audit reports medium-only violations, phase remains active with corrective deadline and mandatory follow-up audit.
3. Corrective closure requires LILITH follow-up audit artifact plus ATHENA alignment confirmation artifact.
