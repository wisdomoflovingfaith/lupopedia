# Doctrine #5: SQL Portability

**Target Compatibility:** MySQL 5.7+, MySQL 8.0+, PostgreSQL 12+, MariaDB 10.2+

**Forbidden Features:**
- ❌ NO UNSIGNED types (PostgreSQL incompatible)
- ❌ NO DATETIME/TIMESTAMP types (use BIGINT YYYYMMDDHHIISS)
- ❌ NO triggers, procedures, functions (application logic only)
- ❌ NO foreign keys (application-managed relationships)
- ❌ NO database-specific functions (vendor lock-in)
- ❌ NO partial indexes with WHERE clause (MySQL 8.0.13+ only)
- ❌ NO display widths on integers (BIGINT(14) → BIGINT)
- ❌ NO AUTO_INCREMENT on non-primary keys
- ❌ NO vendor-specific collations (utf8mb4_unicode_ci only)

**Required Practices:**
- ✅ All INSERT/UPDATE must list every column including PK
- ✅ Use prepared statements with named placeholders
- ✅ Test on minimum supported version (MySQL 5.7)
- ✅ Include filter columns in indexes instead of WHERE clauses
- ✅ Use BIGINT for all integer types (no display widths)

**Recent Fixes (v4.0.46):**
- Fixed partial index WHERE clauses (install_new_lupopedia.sql lines 764-767)
- Solution: Added filter column to index definition for MySQL 5.7 compatibility

**Rationale:** Single codebase, multiple database engines, zero vendor lock-in.
